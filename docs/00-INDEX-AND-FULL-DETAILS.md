## 1. ما هو Second Brain؟ وما هدفه؟

**Second Brain** (العقل الثاني) نظام شخصي يعمل على أجهزة القائد، ويجمع في مكان واحد كل ما يحتاجه لإدارة حياته الرقمية ومشاريعه البرمجية، ولحماية عائلته إن غاب.

### المشكلة التي يحلّها
- **الأسرار مبعثرة:** كلمات المرور، والإيميلات، وأكواد الاسترداد، ومفاتيح API، وملفات التوقيع (`keystore`)، وملفات `.env`، موزّعة بين أجهزة وملفات وذاكرة شخص واحد.
- **المشاريع متعددة:** لكل مشروع أوامر تشغيل، واستضافة، وفواتير، ودخل، وملفات حساسة، ولا يوجد سجل واحد يجمعها.
- **أدوات الذكاء بلا ذاكرة مشتركة:** Claude Code و Antigravity لا يعرف أحدهما ما قرره الآخر، ولا يعرفان صاحب المشاريع.
- **العائلة لا تعرف ماذا تفعل** إن تعطّل الحاسوب أو غاب القائد: أين الحسابات؟ أي المشاريع تدرّ دخلاً؟ كيف تتعامل مع المبرمجين بأمان؟

### الهدف
1. **خزنة واحدة مشفرة** لكل الأسرار، تُفتح بكلمة مرور القائد، أو بمفتاح طوارئ مطبوع للعائلة.
2. **رادار للمشاريع** يفحصها ويوثّقها ويحمي ملفاتها الحساسة ويتابع تغيّرها.
3. **ذاكرة مشتركة** بين أدوات الذكاء، فيعرف كل وكيل ملف القائد وسياق المشروع والقرارات السابقة.
4. **مساعد ذكي بالعربية** يجيب عن المشاريع والحالة، بوضع للقائد ووضع مبسّط للعائلة، بلا فواتير إضافية.
5. **خطة طوارئ عائلية** كاملة: كتيب مطبوع، ونسخ احتياطية مشفرة تُستعاد حتى على جهاز جديد، ودليل مكتوب بلغة بسيطة.
6. **عمل على عدة أجهزة** (لابتوب، ماك، مكتبي قوي) مع مزامنة مشفرة.

### الفائدة باختصار
- **راحة البال:** كل شيء مرتب ومحمي ومنسوخ، والعائلة تعرف الطريق.
- **سرعة العمل:** يسأل القائد المساعد بدل البحث، وتعرف أدوات الذكاء السياق بدل إعادة الشرح.
- **أمان حقيقي:** تشفير عسكري، والبيانات لا تخرج من أجهزته إلا مشفرة.
- **لا اشتراكات جديدة:** يستعمل اشتراك Claude Pro الموجود، ونماذج محلية مجانية.

## 2. الفكرة العامة ومبادئ التصميم

| المبدأ | المعنى العملي |
| :--- | :--- |
| **محلي أولاً** | البرنامج خادم صغير على الجهاز نفسه (`127.0.0.1`)، والواجهة صفحة تُفتح في نافذة مستقلة. لا يوجد خادم مركزي، ولا يعتمد على الإنترنت ليعمل |
| **الخصوصية** | الأسرار لا تُكتب على القرص إلا مشفرة، ولا تُرسل لأي ذكاء اصطناعي. ما يخرج من الجهاز (المزامنة، النسخ) مشفر دائماً |
| **بلا حزم خارجية** | الكود مكتوب بـ Node.js 24 و TypeScript فقط، بلا أي حزمة npm، حتى يبقى يعمل بعد سنوات، ومن فلاشة USB |
| **العربية أولاً** | الواجهة، والرسائل، والأخطاء، والتعليقات داخل الكود، والوثائق، كلها بالعربية |
| **العائلة جزء من التصميم** | وضع عائلة مبسّط، ومفتاح طوارئ مطبوع، ودليل مكتوب لزوجة القائد |
| **لا فواتير إضافية** | الذكاء عبر اشتراك Claude Pro (Claude Code) أو Ollama المجاني. مفاتيح API خيار متقدم مطفأ |
| **كل شيء مختبر وموثّق** | أكثر من 80 فحصاً دائماً، وكل تغيير يرفع رقم الإصدار ويُوثَّق (الدستور) |

**الصورة الكاملة في جملة:** كل جهاز يشغّل Second Brain كاملاً وحده. الخزنة والمشاريع والذاكرة والمحادثات و Obsidian تنتقل بين الأجهزة بنسخ مشفرة عبر Google Drive. أدوات الذكاء (Claude Code و Antigravity) تتصل بذاكرته عبر MCP. والعائلة تستطيع الوصول إلى الضروري بمفتاح الطوارئ.

## 3. الأجهزة والبيئة الحالية

| الجهاز | الاسم في البرنامج | الحالة |
| :--- | :--- | :--- |
| لابتوب Windows (RTX 3050 بذاكرة 4GB) | `DESKTOP-PBQB96B` | العمل اليومي. مثبّت، ويعمل تلقائياً، و XTTS على كرت الشاشة |
| MacBook Air M5 (ذاكرة 16GB) | `MacBook-M5` | مثبّت، ويعمل تلقائياً، و XTTS على المعالج |
| مكتبي قوي (Ryzen 5950X + RTX 3090 بذاكرة 24GB + 48GB) | — | غير مثبّت بعد. دوره في المرحلة د: مزوّد Ollama القوي، ولا يعمل دائماً |

- **الإصدار:** `Second-Brain-System/package.json` هو المصدر الوحيد للإصدار، ويظهر في الواجهة.

- **المتطلبات:** Node.js 24 أو أحدث. وللصوت عالي الجودة Python 3.12 (يُثبَّت في بيئة معزولة داخل المشروع).

## 4. التشغيل

### 4.1 التثبيت (مرة واحدة لكل جهاز)
**Windows** (لا يحتاج صلاحيات مسؤول):
```powershell
powershell -ExecutionPolicy Bypass -File Second-Brain-System\install\windows\install-windows.ps1
```
- يعرض ما سيفعله أولاً، ويدعم `-Preview` للعرض فقط دون تغيير.
- **ينشئ ثلاثة اختصارات فقط:**
  - في مجلد «بدء التشغيل»: تشغيل مخفي عند تسجيل الدخول. يظهر في «مدير المهام ← تطبيقات بدء التشغيل»، ويُعطَّل من هناك.
  - على سطح المكتب وفي قائمة ابدأ: «Second Brain» بأيقونة الدماغ، يفتح النافذة المستقلة.
- **يكتب هوية الجهاز** في `data/device.json` بأداة مشتركة (`install/device-identity.ts`):
  - الملف غير موجود: تُكتب هوية جديدة.
  - موجود لنفس النظام: يبقى.
  - منقول من نظام آخر: يُحفظ نسخةً احتياطية ثم تُكتب هوية جديدة.
- يفحص تسجيل خادم الذاكرة في Claude Code و Antigravity ويعرض حالته فقط، ولا يعدّل إعداداتهما.

**الماك:**
```bash
bash Second-Brain-System/install/macos/install-macos.sh --device-name "MacBook-M5"
```
- **LaunchAgent** باسم `com.secondbrain.server`، بالخيارات:
  - `RunAtLoad`: يعمل عند تسجيل الدخول.
  - `KeepAlive`: يعود إن توقف.
  - `MaterializeDatalessFiles`: يسمح بتنزيل ملفات Google Drive الموجودة في السحابة فقط.
- **ملف «Second Brain.command»** على سطح المكتب لفتح النافذة.

### 4.2 كيف يعمل في الخلفية
- **Windows:** الاختصار يشغّل `start-hidden.vbs`، الذي يشغّل `run-server.ps1` مخفياً.
  - المشغّل يمنع تشغيل نسختين في الوقت نفسه.
  - يعيد تشغيل الخادم إن تعطّل، حتى 5 مرات خلال 10 دقائق، ثم يتوقف حتى لا يدور بلا نهاية.
  - يكتب السجل في `data/logs/server.log`.
- **الخادم** يستمع على `127.0.0.1:4777`، أي هذا الجهاز فقط. عند بدئه:
  - يشغّل المراقب الدوري للمشاريع.
  - يبدأ تحميل الصوت عالي الجودة.
  - يبدأ دورة المزامنة كل دقيقتين.

### 4.3 النافذة المستقلة
اختصار «Second Brain» يشغّل `open-app.ps1`:
1. يتأكد أن الخادم يعمل، ويشغّله إن لم يكن.
2. يفتح الواجهة في **Chrome أو Edge بوضع `--app`**: نافذة خاصة بلا شريط عنوان أو تبويبات، بأيقونة البرنامج في شريط المهام.

### 4.4 التشغيل اليدوي (بديل بلا تثبيت)
- `Launch-Second-Brain.bat` في جذر المشروع، يعمل من أي قرص أو فلاشة. يفتح المتصفح بعد جاهزية الخادم، ويُغلق الخادم بإغلاق نافذته.
- أو من داخل `Second-Brain-System`:
  ```bash
  node src/features/dashboard-app/desktop-server.ts
  ```

### 4.5 الإيقاف والإزالة
```powershell
powershell -ExecutionPolicy Bypass -File Second-Brain-System\install\windows\uninstall-windows.ps1
```
- يحذف الاختصارات الثلاثة، ويوقف المشغّل والخادم.
- **لا يمس أي بيانات:** الخزنة، والمحادثات، والإعدادات، والأصوات تبقى كما هي.
- على الماك: `bash Second-Brain-System/install/macos/uninstall-macos.sh`.

### 4.6 بعد كل تحديث (`git pull`)
**يجب إعادة تشغيل الخادم**، وإلا يبقى يعمل بالكود القديم. منذ 2.1.0:
- يظهر شريط أعلى الواجهة «حُدّث البرنامج… أعد تشغيل الخادم»، مع زر يعيد التشغيل.
- وتتوقف المزامنة حتى إعادة التشغيل (ISS-032).
- و `/api/health` يعرض `version` (الذي يعمل) و `diskVersion` (على القرص).
- **Windows:** أوقف عملية `node` الخاصة بالخادم، فيعيدها المشغّل تلقائياً، أو سجّل الخروج ثم الدخول.
- **الماك:** `launchctl kickstart -k gui/$(id -u)/com.secondbrain.server`.

## 5. الواجهة: كل قسم وما يفعله

**الشريط العلوي:**
- شعار الدماغ، واسم البرنامج.
- مؤشرات سريعة: عدد المشاريع، وحالة الخزنة، وعدد سجلات الذاكرة.
- زرا التبديل: «غرفة القيادة» و«وضع العائلة».

**القائمة الجانبية:** القيادة، المشاريع، الخزنة، الذاكرة، الطوارئ، الربط، المزامنة، الإعدادات.

| القسم | ما فيه |
| :--- | :--- |
| **🎙️ القيادة** | **النواة:** موجة متحركة تنبض مع كتابة الرد ونطقه. **المحادثة مع المساعد:** إرسال، وإدخال بالصوت، ونطق آخر رد، وزر «الرد الصوتي: يعمل/متوقف»، و«المحادثات المحفوظة»، و«محادثة جديدة». **سطر المزوّدين** يعرض الترتيب، وأيها متاح ✓ أو غير متاح ✗ |
| **📡 المشاريع** | بطاقة لكل مشروع: التقنيات، والفرع، وحالة تأمين الملفات الحساسة، وتحذير إن رُفع ملف حساس على Git، وأمر التشغيل، وآخر commit. زر «مشروع جديد» |
| **صفحة المشروع** | تُفتح بالضغط على بطاقته. فيها: ما هو المشروع، وخلاصة يولّدها الذكاء أو تُكتب يدوياً، والأوامر مع زر نسخ، وحالة Git، والملفات الحساسة، وسجل التغييرات، والقرارات من الذاكرة، والمحادثات المؤرشفة. وأزرار: فتح المجلد، فتح في VS Code، إعادة الفحص، «📍 مكانه على هذا الجهاز»، تعديل، إيقاف المراقبة |
| **🔐 الخزنة** | فتح بكلمة المرور أو مفتاح الطوارئ. بطاقات الأسرار بفئات (إيميل، كلمة مرور، مفتاح API، كود استرداد، فواتير)، والقيمة مخفية حتى تُكشف. ملاحظات للقائد وملاحظات للعائلة. ومفاتيح API في قسم متقدم |
| **🧠 الذاكرة** | سجلات الذاكرة المشتركة (من Claude Code و Antigravity والمساعد)، وزر سحب المحادثات المؤرشفة يدوياً |
| **🛡️ الطوارئ** | كتيب الطوارئ للطباعة، والنسخ الاحتياطية المشفرة (إنشاء وسرد)، والاستعادة إلى مجلد جديد |
| **🔌 الربط** | بطاقة «Claude عبر اشتراكك» مع خطوات التسجيل وزر الاختبار. وشرح Gemini عبر Antigravity. وبطاقة Ollama مع اقتراح نماذج لكل جهاز. وبطاقة «🔊 الصوت العربي» لحالته واختيار الصوت وتجربته وتنزيله. ومفاتيح API (متقدم). وشرح ربط الذاكرة بـ MCP |
| **🔄 المزامنة** | آخر نشر ودمج، والأجهزة وإصداراتها، وزر «زامن الآن»، والتعارضات (النسختان جنباً إلى جنب مع «أبقِ» أو «اعتمد الأخرى»)، وسلة المحذوفات مع الاسترجاع، وإعداد المجلد مع اقتراح مجلد Google Drive تلقائياً |
| **⚙️ الإعدادات** | تطلب كلمة المرور الرئيسية في كل مرة (صلاحية 5 دقائق). فيها: الهوية، والذكاء (الوضع، ونموذج Claude عبر الاشتراك، ومسار Claude Code، ومتقدم: مفاتيح API ونماذجها، ونموذج Ollama وعنوانه)، والصوت، والموصلات والمراقب، والأمان والنسخ (القفل التلقائي، وعدد النسخ، ومجلد النسخ الإضافي)، ومنطقة الخطر في وضع التطوير |
| **❤️ وضع العائلة** | واجهة مبسطة بخط كبير: سؤال المساعد بلغة بسيطة، و«استمعي»، و«المحادثات السابقة»، والمشاريع بملخص مفهوم. تُفتح بمفتاح الطوارئ، ولا تصل إلى أدوات القائد |

**شريط التعارضات:** يظهر أعلى الصفحة حين يوجد تعارض في المزامنة ينتظر قرارك (منذ 2.0 لا يوجد وضع قراءة).

## 6. الميزات بالتفصيل

### 6.1 الخزنة المشفرة
**الملف:** `src/features/vault/vault-manager.ts`، والتشفير في `src/core/crypto-engine.ts`.

- **التشفير:** AES-256-GCM. هذا تشفير مع توقيع مصادقة، فأي تعديل على الملف يُكتشف ويُرفض.
- **مفتاح البيانات (DEK):** مفتاح عشوائي طوله 256 بت يشفّر أسرار القائد ومحادثاته ونسخه. يُغلَّف **بكلمة المرور الرئيسية وحدها** (`commanderWrap`). تغيير كلمة المرور يعيد تغليف المفتاح فقط، ولا يعيد تشفير البيانات.
- **الخزنة العائلية (v3، منذ 3.0.0):**
  - **مفتاح عائلي مستقل (FK)** يشفّر قسم `family` في ملف الخزنة: الأسرار المعلَّمة «👪 يظهر للعائلة»، بلا ملاحظات القائد ولا الملفات الحساسة التقنية.
  - المفتاح العائلي **مختوم بمفتاح البيانات** (`fkByCommander`، فيفتحه القائد تلقائياً)، و**ملفوف بمفتاح الطوارئ** (`fkByEmergency`).
  - **مفتاح الطوارئ لا يصل إلى مفتاح البيانات أبداً.** قبل 3.0.0 كان `emergencyWrap` يفتح كل شيء (ISS-017).
  - الخزنة العائلية تُعاد كتابتها من الأسرار المعلَّمة عند كل حفظ، فالعلامة مصدر واحد للحقيقة.
  - **الترقية** من v2 يدوية، مرة واحدة على جهاز واحد (بطاقة «👪 الخزنة العائلية» في قسم الطوارئ)، مع مفتاح طوارئ جديد إجبارياً. الأجهزة الأخرى تُرقّى بالمزامنة بالمفتاح العائلي نفسه.
- **اشتقاق المفتاح من كلمة المرور:** scrypt بمعاملات `N=131072, r=8, p=1`. هذا يجعل تخمين كلمة المرور بطيئاً جداً.
- **كلمة المرور الرئيسية:** 10 أحرف على الأقل.
- **مفتاح الطوارئ:** 128 بت، بصيغة `SB-XXXX-XXXX-…-XXXX-CCCC`: ثماني مجموعات، ثم مجموعة تحقق أخيرة تكشف أي خطأ عند كتابته يدوياً. يظهر **مرة واحدة فقط** عند الإنشاء، ثم يُطبع في الكتيب. يمكن تدويره، فيبطل المفتاح القديم.
- **الحفظ ذرّي:** يُكتب ملف مؤقت ثم يُستبدل، مع خمس نسخ سابقة (`.bak-1` … `.bak-5`)، فلا يتلف الملف إن انقطع الكهرباء.
- **الخزنة لا تُمسح أبداً:** الإنشاء يرفض العمل فوق خزنة موجودة.
- **الجلسة:**
  - فتح الخزنة ينشئ جلسة بكوكي آمن.
  - **قفل تلقائي** بعد 10 دقائق بلا نشاط (قابل للتغيير).
  - المحاولات الخاطئة تُبطئ المحاولة التالية تصاعدياً، حتى 5 دقائق.
- **مستويا الوصول:**
  - **القائد** (كلمة المرور): كل شيء.
  - **العائلة** (مفتاح الطوارئ): الخزنة العائلية وحدها، ومحادثات العائلة، ووضع العائلة. جلستها بلا مفتاح بيانات: لا إعدادات، ولا تعديل، ولا مزامنة، ولا نسخة كاملة، ولا أدوات خطرة.
- **الملفات الحساسة للمشاريع** (`.env`، keystore…) تُنسخ مشفرة داخل الخزنة (حتى 5MB للملف)، وتُستعاد عند الحاجة.

- **قياس دعم Passkeys (منذ 3.2.0، تمهيداً للمرحلة 2.2):** بطاقة «🧪 قياس دعم البصمة والوجه» في قسم الخزنة. تنشئ Passkey تجريبياً وتتحقق منك مرتين بامتداد PRF، ثم تصنّف الجهاز: **prf** (الطريقة الأولى)، أو **keystore** (البديل: مخزن مفاتيح النظام)، أو **unsupported**. ناتج PRF لا يغادر المتصفح، والتقرير في `data/passkey-probe/`. **تعمل على `http://localhost` فقط** (WebAuthn يرفض `127.0.0.1`)، والمشغّلات كلها تفتح `localhost` (ISS-037).

### 6.3 الذاكرة المشتركة وخادم MCP
**الملفات:** `src/features/ai-memory/`، و `src/tools/mcp-memory-server.ts`

- **الذاكرة المشتركة** (`data/ai-memory-store.json` ونسخة في Obsidian): سجلات «ماذا أُنجز وما القرارات»، من أي أداة ذكاء، مربوطة بمشروع. **الأسرار تُحذف تلقائياً** قبل الحفظ.
- **خادم MCP** (بروتوكول Model Context Protocol عبر stdio): تشغّله أدوات الذكاء نفسها، وفيه 6 أدوات:

| الأداة | ماذا تفعل |
| :--- | :--- |
| `second_brain_get_commander_profile` | ملف القائد: من هو وأسلوبه ومعاييره |
| `second_brain_get_commander_and_projects_context` | الملف + ملخص كل المشاريع |
| `second_brain_get_project_context` | سياق مشروع واحد بالتفصيل |
| `second_brain_recall_shared_memory` | استرجاع قرارات مشروع |
| `second_brain_search_memory` | البحث في الذاكرة |
| `second_brain_record_shared_memory` | تسجيل ملخص عمل وقرارات |

- **مسجّل في:** Claude Code (`~/.claude.json`) و Antigravity (`~/.gemini/antigravity/mcp_config.json`) على Windows. على الماك يُسجَّل يدوياً حسب `docs/08`.
- **أرشفة المحادثات** (`transcript-harvester.ts` والموصلات):
  - يقرأ سجلات Claude Code (`~/.claude/projects`) و Antigravity (`~/.gemini/antigravity/brain`).
  - يحذف الأسرار، ويحفظها في Obsidian داخل مجلد المشروع المعني (`AI-Conversations`) أو في `03-AI-Shared-Memory/*-Sessions`.
  - **تزايدي:** لا يعيد ما لم يتغير.
  - جلسات الوكلاء الفرعيين الداخلية في Antigravity (رسائل نظام بلا سؤال من القائد) تُتجاهل عمداً.

### 6.4 المساعد الذكي ومزوّدو الذكاء
**الملفات:** `src/features/assistant/`

- **وضعان:**
  - **القائد:** تفصيلي وتقني.
  - **العائلة:** لغة بسيطة، بلا مصطلحات، ويركّز على ما يهم الأسرة.
- **السياق المرسل للنموذج:** ملف القائد، وبيانات المشاريع، والذاكرة. **محتوى الخزنة لا يُرسل أبداً،** والأسرار تُحذف من أي نص.
- **ترتيب المزوّدين الافتراضي، بلا فواتير إضافية:**
  1. **Claude عبر الاشتراك** (`claude-cli`): يشغّل Claude Code دون واجهة (`claude -p`) باشتراك Pro نفسه. معزول تماماً:
     - بلا أدوات، وبلا خوادم MCP، وبلا مهارات، وبلا إعدادات مستخدم أو مشروع، وبلا حفظ جلسات.
     - يعمل في مجلد مؤقت فارغ يُحذف بعد كل رد.
     - إن ظهرت أي أداة عند البدء يُوقَف فوراً.
     - تُزال مفاتيح API من بيئته حتى لا تتحول الفوترة إليها.
     - النموذج الافتراضي `sonnet` لتوفير الحصة.
  2. **Ollama:** نماذج محلية مجانية على الجهاز نفسه (`http://127.0.0.1:11434`).
  3. **المعرفة المحلية:** تجيب من بيانات المشاريع دون أي اتصال. تعمل دائماً.
- **أوضاع الإعداد:** هجين (الاشتراك ثم Ollama)، أو اشتراك Claude فقط، أو محلي (Ollama فقط).
- **التراجع التلقائي:** المزوّد غير المتاح يُتخطى فوراً، ومنه Claude غير المسجّل الدخول و Ollama المتوقف. وإن فشل مزوّد بعد أن بدأ الرد يُمسح النص الجزئي ويُجرَّب التالي.
- **مفاتيح API (متقدم ومطفأ):** Claude API و Gemini API، تُحفظ مشفرة في الخزنة، ولا تُستخدم إلا بتفعيل «استخدام مفاتيح API». **فوترة منفصلة.**
- **Gemini:** مربوط عبر Antigravity والذاكرة المشتركة فقط، لأن Google رفضت Gemini CLI لحسابات الأفراد.
- **البث:** الرد يظهر حرفاً بحرف (SSE)، والموجة تنبض معه.
- **زر «اختبار الاتصال» لكل مزوّد:** رسالة ثابتة بلا معلومات شخصية، وزمن الاستجابة، وسبب الفشل والحل بالعربية.
- **القرار المعتمد** ([`docs/07`](07-EXPANSION-PLAN.md)):
  - مكوّنان فقط: Claude Code و Ollama.
  - OpenCode مستبعد.
  - واجهة NVIDIA السحابية مؤجلة.
  - موديلات NVIDIA المفتوحة مسموحة داخل Ollama.

**الملفات:** `src/features/voice/`

     - الرخصة: Coqui Public Model License، للاستخدام الشخصي غير التجاري (وافق عليها القائد).
  2. **احتياط أثناء تحميل XTTS:**
     - **Windows:** Piper بصوت «Kareem».

- **لا ينطق أبداً بصوت إنجليزي:** إن لم يوجد صوت عربي يشرح طريقة الحل.
- **التثبيت على جهاز آخر:**
  - `node src/tools/install-xtts-voice.ts --accept-license` (نحو 4.8GB).
  - Kareem على Windows: `node src/tools/install-arabic-voice.ts`.
  - كل ذلك في `vendor/`، ولا يُرفع إلى Git.
- **الإدخال الصوتي:** زر «🎤 بالصوت» يستعمل التعرف على الكلام في المتصفح.

### 6.7 العائلة والطوارئ والنسخ الاحتياطي
**الملفات:** `src/features/family-emergency/`، و `Obsidian-Vault/04-Family-Emergency-Guide/`

- **كتيب الطوارئ:**
  - صفحة للطباعة تُولَّد في الذاكرة فقط، ولا تُحفظ على القرص.
  - فيها مفتاح الطوارئ، وخطوات فتح الخزنة، وجدول المشاريع والدخل.
- **دليل العائلة في Obsidian** (أربعة ملفات): رسالة ودليل البداية، وجدول المشاريع والفواتير والدخل، وكيف تتعامل مع المبرمجين بأمان، والتشغيل على جهاز جديد.
- **النسخ الاحتياطية المشفرة** (`backup-service.ts`):
  - **المحتوى:** Obsidian، والخزنة، والإعدادات، والذاكرة، والمحادثات.
  - **الصيغة 3 (منذ 3.0.0) فيها حمولتان:**
    - **كاملة** بمفتاح البيانات، تُفتح **بكلمة المرور** وحدها.
    - **عائلية** بالمفتاح العائلي، تُفتح **بمفتاح الطوارئ**: ملف الخزنة، والإعدادات، والهوية، وأدلة العائلة، ودليل كل مشروع للعائلة، ومحادثات العائلة.
  - **الفتح:** حتى على جهاز جديد بلا خزنة. الصيغة 2 القديمة تُقرأ فقط.
  - **النسخ القديمة** التي يفتحها مفتاح الطوارئ القديم تظهر في «🗂️ نسخ قديمة…»، وتُحذف بكلمة المرور فقط.
  - **الحفظ:** تُحفظ في `data/encrypted-backups/`، وتُنسخ أيضاً إلى «مجلد النسخ الإضافي». حالياً `G:\My Drive\Second Brain\Backups`.
  - **الاحتفاظ:** آخر 10 نسخ.
- **الاستعادة:** إلى مجلد جديد أو فارغ فقط، فلا تُكتب فوق البيانات الحالية. مع معاينة قبل الكتابة.
- **اختبار التعافي من الكوارث:** محاكاة كاملة لدليل «جهاز جديد» من البداية للنهاية (`tests/08`).
- **بوابة العائلة (منذ 3.1.0، `family-portal.ts`):** كل ما فيها داخل الخزنة العائلية، فيفتحه مفتاح الطوارئ.
  - **📞 جهات الاتصال** و **🧭 تعليمات التعامل مع المطورين والشركات:** يكتبها القائد من بطاقة «👪 بوابة العائلة» في قسم الطوارئ. عنصران في الخزنة (`contact` و `family_instruction`) معلَّمان للعائلة دائماً، ولا يظهران في قائمة الأسرار.
  - **🧾 الفواتير المتكررة:** أسرار الفواتير المعلَّمة للعائلة، وفواتير المشاريع.
  - **📝 سجل خطوات الطوارئ** (`data/family-log/`): فتح الخزنة العائلية وقفلها، وأسئلة المساعد (أول 120 حرفاً)، وحذف المحادثات، وملاحظات العائلة. مختوم بالمفتاح العائلي وحده، ولا يُعدَّل ولا يُحذف. يُزامَن (`flog`) ويدخل الحمولة العائلية، وتمرين الاستعادة يفحصه.
  - **في وضع العائلة:** خطوات «بمن تتصلين»، والتعليمات، والفواتير، و«سجل ما فعلتِه». والمساعد العائلي يعرف جهات الاتصال والتعليمات.

### 6.8 المزامنة بين الأجهزة (2.0: الكتابة من كل الأجهزة)
**الملفات:** `src/features/sync/`. **القرارات:** [`docs/11`](11-IDEAS-DISCUSSION-DECISIONS.md)، الموضوع 1. **الخطة:** [`docs/12`](12-EXECUTION-PLAN.md)، المرحلة 1.

- **الفكرة:** كل جهاز يعمل محلياً، و**تكتب وتعدّل من أي جهاز** متى شئت. التغييرات تنتقل **مشفّرة بمفتاح الخزنة** عبر مجلد Google Drive، فلا يرى Google أي محتوى.
- **المجلد المعتمد:** `My Drive/Second Brain/` (على الماك العربي «ملفاتي/Second Brain»)، وفيه:
  ```text
  Second-Brain-Sync/
  ├── changes/<الجهاز>/     ← دفعات التغييرات المشفّرة؛ كل جهاز يكتب في مجلده فقط
  ├── snapshots-v2/         ← نسخ كاملة مشفّرة أسبوعية (لإقلاع جهاز جديد)، آخر 10
  ├── devices/              ← ملف حالة لكل جهاز (آخر ظهور، الإصدار، التعارضات، آخر تغيير في كود كل مشروع)
  ├── manifest.json, snapshots/, write-lease.json ← من 1.9: للقراءة، وقفل الأجهزة القديمة فقط
  Backups/                  ← نسخ الطوارئ الإضافية
  ```
- **ما يُزامَن (سجلّاً سجلّاً):**
  - كل سرّ وحده، ومغلّفا المفتاح، والهوية.
  - كل سجل ذاكرة، وكل مشروع، وكل محادثة.
  - كل ملف Obsidian، ما عدا `workspace*.json` و `.trash`.
- **ما لا يُزامَن:** إعدادات كل جهاز (الذكاء، والصوت، والمجلد، والأمان)، وهويته، ومسارات مشاريعه، و `data/sync/`، والسجلات، و `vendor/`.
- **الدورة** (كل دقيقتين، وعند فتح الخزنة وقفلها، وبزر «زامن الآن»):
  1. كشف التغييرات المحلية ونشرها دفعةً مشفّرة.
  2. دمج دفعات الأجهزة الأخرى، بعد نسخة احتياطية محلية، كمعاملة واحدة تعود كما كانت إن فشلت.
  3. ضغط أسبوعي، وتفريغ السلة بعد 30 يوماً.
- **كيف يُعرف الأحدث:**
  - لكل سجل «متجه إصدارات»: كم مرة عدّله كل جهاز.
  - وختم «العدّاد الذكي» (HLC) لا يتأثر بساعة جهاز متقدمة أو متأخرة.
- **التعارض** (تعديلان لم يرَ أحدهما الآخر):
  - تُحفظ النسختان. الأحدث معتمد، والأخرى في قائمة التعارضات.
  - في Obsidian تُكتب الأخرى نسخة جانبية: `الاسم (تعارض - الجهاز - التاريخ).md`.
  - **الأسرار لا تُحسم تلقائياً أبداً**، فيبقى كل جهاز على قيمته حتى تختار.
  - حذف مقابل تعديل: يبقى التعديل ويعود إلى الجهاز الذي حذف.
  - كلمة المرور: الأحدث يفوز مع إشعار.
- **السلة:** كل محذوف يبقى 30 يوماً على كل جهاز، والاسترجاع من أي جهاز يعيده للجميع.
- **الحذف الجماعي** (10 عناصر فأكثر، أو مجلد كامل): لا يُنشر ولا يُطبَّق بلا تأكيدك. تظهر بطاقة «🛑 حذف جماعي ينتظر تأكيدك» (ISS-028).
- **حارس الإصدار:**
  - دفعة بصيغة أحدث لا تُدمج.
  - جهاز أقدم من `minAppVersion` في `manifest.json` (الآن 2.2.0) يتوقف ويطلب التحديث.
  - خادم بكود أقدم من القرص يوقف المزامنة حتى إعادة التشغيل (ISS-032).
- **الوثائق المولّدة للمشاريع** (`01`–`06` في Obsidian): يكتبها فقط الجهاز صاحب آخر تغيير في كود المشروع. وإن تعارضت تُحسم بصمت (الأحدث، والأخرى في السلة) بلا بطاقة تعارض.
- **الأسماء العربية:** تُوحَّد بصيغة يونيكود NFC، لأن الماك يعيدها مفكّكة. على Windows يُوحَّد أي اسم مكرر تلقائياً (ISS-025).
- **لا يُزامَن أيضاً:** `00-Command-Center/Code-Registry-Mirror.md`، لأنه يصل عبر Git.
- **بعد كل `git pull` يُعاد تشغيل الخادم على كل جهاز:** العملية القديمة تبقى بالكود القديم في الذاكرة، وجهاز بإصدار أقدم قد يطبّق صيغة جديدة خطأً (ISS-028).
- **الحمايات:**
  - دفعة لم يكتمل تنزيلها تؤجَّل ولا تُعدّ محذوفة (ISS-013).
  - دفعة من خزنة مختلفة تُترك.
  - مسارات Obsidian تُفحص فلا تخرج من المجلد.
  - لا جهاز يحذف ملفات جهاز آخر.
- **الترحيل من 1.9** (مرة واحدة، تلقائياً عند أول فتح بكلمة المرور الرئيسية):
  - استيراد آخر نسخة قديمة، ثم نسخة احتياطية، ثم بناء الفهرس من الأساس المشترك (لا تعارضات وهمية).
  - ثم قفل الأجهزة القديمة: أي جهاز بإصدار 1.9 يبقى في وضع القراءة حتى يُحدَّث.
- **جهاز جديد** (المكتبي، أو Android لاحقاً): يُقلع من أحدث نسخة كاملة بكلمة المرور (`bootstrapFromSnapshotV2`)، ثم الدفعات اللاحقة. واجهته تأتي مع المرحلة 5.
- **تمرين الاستعادة** (قسم الطوارئ): يجد النسخ في المجلد المحلي، والإضافي، و`<مجلد المزامنة>/Backups` على Drive تلقائياً، ويختار الأحدث، ويعرض مكانها وعمرها، ويُنبّه إن كانت أقدم من 7 أيام.
- **حدّ معروف:** الدورة تحتاج الخزنة مفتوحة (لفك التشفير). ما يتغيّر والخزنة مقفلة يُنشر عند فتحها.

### 6.9 الإعدادات ووضع التطوير
- **الإعدادات** مقسومة على ملفين:
  - `config/branding.json`: الهوية والأسماء (يُزامَن).
  - `config/settings.json`: كل الباقي، وهو خاص بالجهاز ما عدا قائمة المشاريع.
- **الدخول إلى الإعدادات** يتطلب كلمة المرور الرئيسية في كل مرة، بصلاحية 5 دقائق. مفتاح الطوارئ لا يفتحها.
- **وضع التطوير** (`developerMode`، مفعّل افتراضياً):
  - **«تصفير»** ينقل كل البيانات إلى سلة قابلة للاسترجاع (`data/_trash/<تاريخ>`).
  - **«استرجاع آخر تصفير»** يحفظ الحالة الحالية في السلة أولاً.
  - **«إفراغ السلة»** حذف نهائي.
  - **«الاعتماد النهائي»** يطفئ وضع التطوير من جهة الخادم.
  - كل عملية تتطلب عبارة تأكيد مكتوبة: «تصفير»، و«إفراغ السلة»، و«اعتماد نهائي».
  - **التصفير لا يمس:** الكود، والوثائق، وملف القائد، ودليل العائلة، والنسخ الاحتياطية.

## 7. الأمان والخصوصية

### 7.1 طبقات الحماية في الخادم
- **الاستماع:** على `127.0.0.1` فقط، فلا يصل إليه أي جهاز آخر في الشبكة.
- **حماية الطلبات:**
  - **Host / Origin:** أي طلب من مصدر غير واجهة البرنامج يُرفض (حماية من CSRF ومن DNS rebinding).
  - **JSON فقط:** طلبات الكتابة تقبل `application/json` فقط، وبحد أقصى 1MB للطلب.
  - **جلسة الخزنة:** في كوكي `HttpOnly`، وتنتهي بالقفل التلقائي.
- **سياسة أمان المحتوى (CSP) الصارمة:** لا سكربتات ولا أنماط مضمّنة، ولا تحميل من أي موقع خارجي. الصوت المولّد يُشغَّل من `blob:` فقط.
- **كل نص في الواجهة** يُعرض عبر `textContent`، فلا يمكن حقن HTML (XSS).
- **الصلاحيات:** مسارات للقائد فقط (`commanderOnly`)، وومسارات تتطلب الخزنة (`requiresSession`). (`sharedWrite` ووضع القراءة أُزيلا في 2.0.)

### 7.2 ماذا يخرج من الجهاز؟
| ما يخرج | إلى أين | كيف |
| :--- | :--- | :--- |
| سؤالك وسياق المشاريع (بلا أسرار ولا خزنة) | Anthropic، عبر Claude Code باشتراكك | فقط إن كان Claude المزوّد المستخدم |
| نسخ المزامنة | Google Drive | **مشفرة بمفتاح الخزنة**؛ Google لا يرى المحتوى |
| نسخ الطوارئ الإضافية | Google Drive | **مشفرة** |
| الكود والوثائق | GitHub (عام) | بعد فحص لكل commit بحثاً عن بريد أو أسرار أو بيانات شخصية |

**ما لا يخرج أبداً:**
- محتوى الخزنة لأي ذكاء اصطناعي.
- الصوت، فيُولَّد محلياً.
- Ollama والمعرفة المحلية، فهما محليان بالكامل.
- مجلد `data/` و `vendor/` والإعدادات الحقيقية إلى GitHub.

### 7.3 قواعد ملزمة (من الدستور)
1. الخزنة لا تُمسح ولا تُعاد تهيئتها أبداً.
2. لا يُكتب سر على القرص بنص مكشوف.
3. الأسرار تُحذف تلقائياً من المحادثات المؤرشفة والذاكرة وسياق المساعد.
4. تسجيل الدخول لأي حساب يقوم به القائد بنفسه.
5. أي تعديل على إعدادات برامج أخرى يُعرض أولاً مع نسخة احتياطية.
6. الرفع إلى GitHub بموافقة القائد الصريحة فقط.

## 9. البنية البرمجية

### 9.1 التقنيات
- **Node.js 24+** يشغّل ملفات TypeScript مباشرة، بلا بناء ولا حزم npm.
- **الوحدات المدمجة فقط:** `node:http` و `node:crypto` و `node:fs` و `child_process`…
- **Python 3.12** معزول في `vendor/xtts-venv` للصوت عالي الجودة فقط (PyTorch و coqui-tts).
- **PowerShell و VBScript** لمثبّت Windows، و **bash و launchd** لمثبّت الماك.
- **Obsidian** لتصفّح المعرفة (اختياري)، و **Google Drive for desktop** للمزامنة.

### 9.2 الطبقات (القانونان 2 و 3)
```text
src/shared/    ← أنواع ودوال مشتركة (لا يعتمد على شيء)
src/core/      ← الإعدادات، التشفير، السجل (يعتمد على shared فقط)
src/features/  ← كل ميزة في مجلد: vault، project-indexer، ai-memory، assistant، conversations،
                 voice، sync، family-emergency، maintenance، dashboard-app
src/tools/     ← أدوات مستقلة: خادم MCP، فهرس الدوال، تثبيت الأصوات
install/       ← المثبّتان، والمشغّل في الخلفية، وهوية الجهاز، والأيقونة
tests/         ← 15 حزمة اختبار دائمة ومعزولة
```
الشجرة الكاملة بكل ملف في [`docs/01-ARCHITECTURE-TREE.md`](01-ARCHITECTURE-TREE.md)، وفهرس كل دالة (يُولَّد آلياً) في [`docs/04`](04-CODE-AND-FUNCTIONS-INDEX.md).

## 16. مسرد المصطلحات

| المصطلح | المعنى |
| :--- | :--- |
| **الخزنة (Vault)** | ملف مشفر يحوي كل الأسرار |
| **مفتاح البيانات (DEK)** | المفتاح العشوائي الذي يشفّر الخزنة والنسخ والمحادثات، مغلّف بكلمة المرور وحدها (منذ 3.0.0) |
| **المفتاح العائلي (FK)** | مفتاح الخزنة العائلية ومحادثات العائلة والحمولة العائلية في النسخ. يفتحه القائد تلقائياً، والعائلة بمفتاح الطوارئ |
| **مفتاح الطوارئ** | مفتاح مطبوع للعائلة يفتح الخزنة العائلية وحدها (منذ 3.0.0) |
| **AES-256-GCM** | خوارزمية تشفير مع توقيع يكشف أي تعديل |
| **scrypt** | طريقة بطيئة عمداً لاشتقاق مفتاح من كلمة مرور، حتى يصعب تخمينها |
| **MCP** | بروتوكول يسمح لأدوات الذكاء (Claude Code و Antigravity) باستخدام أدوات Second Brain وذاكرته |
| **المزوّد (Provider)** | مصدر الإجابة: Claude عبر الاشتراك، أو Ollama، أو المعرفة المحلية |
| **Ollama** | برنامج مجاني يشغّل نماذج ذكاء اصطناعي على الجهاز نفسه |
| **XTTS-v2 / Piper** | محركا توليد صوت عربي محلياً |
| **النسخة (Snapshot)** | ملف مشفر فيه كل البيانات المشتركة بإصدار معيّن، للمزامنة |
| **manifest.json** | ملف يشير إلى أحدث نسخة على مجلد المزامنة |
| **المزامنة متعددة الكتابة** | كل جهاز يكتب، والدمج سجلّاً بسجلّ (2.0) |
| **متجه الإصدارات** | لكل سجل: كم مرة عدّله كل جهاز، فيُعرف الأحدث أو التعارض |
| **التعارض** | تعديلان للسجل نفسه لم يرَ أحدهما الآخر؛ تُحفظ النسختان |
| **قفل الكتابة (Lease)** | من 1.9؛ يبقى في 2.0 فقط لإبقاء الأجهزة القديمة في وضع القراءة |
| **إشارة الحياة (Heartbeat)** | تحديث دوري يثبت أن حامل القفل ما زال يعمل |
| **المطابقة التامة** | عند الاستيراد يصبح المجلد مطابقاً للنسخة، بما في ذلك حذف ما حُذف |
| **LaunchAgent** | آلية macOS لتشغيل برنامج تلقائياً عند الدخول |
| **وضع `--app`** | فتح صفحة في نافذة متصفح بلا شريط عنوان، كأنها برنامج |
| **وضع التطوير** | يسمح بالتصفير أثناء البناء، ويُطفأ عند الاعتماد النهائي |
