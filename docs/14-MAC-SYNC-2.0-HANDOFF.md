## 3. خطوات التشخيص والترحيل على الماك (بالترتيب)

### 3.1 السحب والتأكد من الكود
```bash
cd "<مجلد المشروع على الماك>"
git pull
git log --oneline -3
grep '"version"' Second-Brain-System/package.json
```
- **المتوقع:** آخر commit هو `v2.0.1…`، والإصدار `2.0.1`.
- **ثم الاختبارات:**
```bash
cd Second-Brain-System && node tests/run-all-tests.ts
```
- **المتوقع:** 100/100. إن فشل اختبار على الماك فقط، فهذا خلل يُسجَّل في `docs/13`. انتبه خصوصاً لاختبار الأسماء العربية (ISS-024)، فسلوك `fs.rmSync` على الماك قد يختلف.

### 3.2 إعادة تشغيل الخادم والتأكد أنه الكود الجديد
```bash
launchctl kickstart -k gui/$(id -u)/com.secondbrain.server
```
```bash
curl -s http://127.0.0.1:4777/api/sync/status
```
- **دليل الكود الجديد:** الرد فيه `"multiWriter":true`. إن لم يوجد، فالخادم ما زال قديماً.
- **إن لم ينفع `kickstart`:** أعد تشغيل المثبّت، أو أوقف العملية.
```bash
pgrep -fl desktop-server
```
- **في المتصفح:** حدّث الصفحة تحديثاً كاملاً (Cmd+Shift+R)، حتى لا تبقى نسخة قديمة من `app.js`.

### 3.3 فتح الخزنة (الترحيل)
- يفتح القائد الخزنة بكلمة المرور الرئيسية. **Claude لا يُدخل كلمة المرور أبداً.**
- **المتوقع:** رسالة «🎉 رُحّل هذا الجهاز إلى المزامنة الجديدة…»، ومعها «⬆️ نُشر N تغييراً» و«⬇️ دُمج N تغييراً».
- **إن ظهر خطأ قراءة من Google Drive** (`EDEADLK` أو «لم يسمح Google Drive»): ملف النسخة الكاملة الجديد (15.9MB) أو الدفعات لم تُنزَّل بعد.
  - اجعل مجلد `ملفاتي/Second Brain` «متاحاً بلا إنترنت» في Google Drive.
  - تأكد أن مثبّت الماك 1.9.3 أو أحدث (`MaterializeDatalessFiles`).
  - ثم أعد فتح الخزنة.
- **بعد الترحيل:**
```bash
ls "$HOME/Library/CloudStorage/"*/ملفاتي/Second\ Brain/Second-Brain-Sync/changes/
```
  يجب أن يظهر مجلد للماك `a9badde6-…`.

### 3.4 تشخيص التعارضات (إن ظهرت)
- **من الواجهة:** «🔄 المزامنة» ← «⚠️ تعارضات تنتظر قرارك». لكل تعارض: نوع السجل ومساره، والنسختان جنباً إلى جنب.
- **من الطرفية** (للعدد والمفاتيح فقط؛ المحتوى مشفّر):
```bash
ls Second-Brain-System/data/sync/conflicts/ | wc -l
```
```bash
node -e "const i=require('./Second-Brain-System/data/sync/index.json');console.log(i.origin, Object.keys(i.records).length, i.lastError, i.lastWarning)"
```
- **صنّف كل تعارض في القسم 6:**

| النوع | السبب المرجّح | التوصية للقائد |
| :--- | :--- | :--- |
| `obs:02-Projects/<مشروع>/01–06-*.md` | وثائق مولّدة كتبها مراقب كل جهاز قبل 2.0 | «أبقِ المعتمدة الآن» إن كانت الأحدث. لا فقد، فالأخرى نسخة جانبية في السلة. **إن تكرر هذا النوع بعد الترحيل** فهو خلل في `code-ownership.ts` ويُسجَّل |
| `obs:` ملاحظة كتبها القائد | تعديل على الجهازين | القائد يقرأ النسختين ويختار |
| `secret:` | سرّ عُدّل على الجهازين | **لا فائز تلقائي.** القائد يختار. Claude لا يقرأ القيم، فالواجهة تعرضها مخفية |
| `memory:` أو `project:` | سجل عُدّل على الجهازين | القائد يختار |

- **لكل تعارض لا تفسّره الأسباب أعلاه،** ابحث في الكود: `mergeIncoming()` في `src/features/sync/multi-writer-sync.ts`.
  - إن كان تعارضاً **وهمياً** (المحتوى نفسه بفرق تافه، أو سجل لم يُعدَّل على الجهازين)، فهو خلل.
  - يُصلح مع اختبار في `tests/16`، ثم إصدار جديد، ثم يُسجَّل في `docs/13`.

### 3.5 التحقق 1.6 (بعد ترحيل الجهازين)
1. ملاحظة جديدة على الماك تظهر على Windows خلال دقيقتين إلى خمس، والعكس.
2. **تعارض مقصود:** الملاحظة نفسها تُعدَّل على الجهازين قبل المزامنة، فتظهر بطاقة التعارض على الاثنين، ويُحسم من أحدهما فيختفي من الآخر.
3. حذف ملاحظة **باسم عربي** على جهاز يصل إلى الآخر، ويظهر في السلة، ثم «استرجع» يعيده على الجهازين (ISS-024).
4. **تمرين الاستعادة على الماك لنسخة Windows:**
   - أحدث نسخة طوارئ من Windows في `ملفاتي/Second Brain/Backups/` (`…2026-11-16T20-22-45…`، 19.4MB).
   - الزر في «الطوارئ» ← «🧪 تمرين الاستعادة» يأخذ أحدث نسخة في مجلدات النسخ، ومنها المجلد الإضافي إن كان مضبوطاً في الإعدادات.
   - **النسخ قبل 2.0 لا تضم المحادثات (ISS-020).** لذلك «سلامة المحادثات: لا محادثات في هذه النسخة» نتيجة متوقعة، وليست فشلاً.
