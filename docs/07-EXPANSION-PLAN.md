## المرحلة أ — تحسينات الواجهة

### أ.1 الموجة فقط
- حذف أشكال (المدمج، السحابة، الحلقات) وأزرارها من `public/index.html` و `hologram.js`.
- إبطاء الحركة الهادئة إلى نحو النصف.
- **التفاعل مع الرد:** كل جزء نص يصل عبر البثّ يعطي الموجة نبضة متناسبة مع طوله، وتهدأ تدريجياً بعد انتهاء الرد. أثناء النطق تنبض مع كل كلمة (حدث `boundary` في Web Speech API).

### أ.2 الإعدادات بكلمة المرور
- عند فتح قسم الإعدادات تظهر نافذة كلمة المرور الرئيسية **في كل مرة**.
- الخادم يمنح «صلاحية إعدادات» مؤقتة (5 دقائق) مرتبطة بالجلسة، وتُطلب لـ **قراءة** الإعدادات وحفظها.
- مفتاح الطوارئ لا يمنح هذه الصلاحية إطلاقاً.
- اختبار: الإعدادات مرفوضة دون إعادة إدخال كلمة المرور، ومرفوضة بعد انتهاء المهلة، ومرفوضة بمفتاح الطوارئ.

### أ.3 صفحة المشروع
الضغط على أي مشروع يفتح صفحة كاملة فيها:
- **ما هو ولمن:** الوصف، والشرح المبسط للعائلة، والدخل، والفواتير.
- **ملخص ذكي:** زر «اكتب لي ملخصاً» يولّده المساعد من ملفات المشروع وتاريخه، ثم يُحفظ ويمكن تعديله.
- **التشغيل:** أوامر التشغيل والبناء والتحديث مع زر نسخ لكل أمر.
- **Git:** الفرع، وآخر commits، والتغييرات غير المحفوظة، والتحذيرات.
- **الملفات الحساسة** وحالة تأمينها.
- **سجل التغييرات:** آخر الأحداث.
- **الذاكرة:** القرارات المحفوظة عن المشروع، وقائمة محادثات الذكاء المؤرشفة مع إمكانية قراءتها.
- **أزرار:** فتح المجلد، وفتح في VS Code، وإعادة الفحص، وتعديل المعلومات، وإيقاف المراقبة.
- الأزرار التي تفتح برامج على الجهاز تعمل **لمسارات المشاريع المسجّلة فقط** وللقائد فقط.

### أ.4 وضع التطوير وزر التصفير
- إعداد `developerMode` (مفعّل الآن).
- زر «تصفير كل شيء» في الإعدادات: كلمة المرور + كتابة عبارة التأكيد.
- **ينقل إلى السلة** `data/_trash/<التاريخ>/`: الخزنة، والإعدادات الشخصية، والمشاريع، والذاكرة، وحالة السحب والفحص، وما ولّده البرنامج في Obsidian، والسجلات.
- زر «استرجاع آخر تصفير»، وزر منفصل «إفراغ السلة نهائياً».
- عند إطفاء وضع التطوير يختفي الزر **ويرفض الخادم الطلب**، وإطفاؤه يتطلب كلمة المرور.
- لا يمس الكود، ولا الوثائق، ولا النسخ الاحتياطية على الفلاشة أو Drive.
- **المنفَّذ:** `src/features/maintenance/reset-service.ts` و `routes/maintenance-routes.ts` (`/api/maintenance`، `reset`، `restore-last`، `empty-trash`، `finalize`). عبارات التأكيد: «تصفير»، «إفراغ السلة»، «اعتماد نهائي».
  - تبقى إعدادات مسارات الجهاز (`paths`, `serverPort`) بعد التصفير حتى يعرف البرنامج أين يعمل.
  - الاسترجاع لا يحذف الحالة الحالية: يحفظها في السلة أولاً، فيمكن التبديل مرة أخرى.
  - لا يُمس `01-Commander-Profile` ولا `04-Family-Emergency-Guide` (مكتوبان يدوياً).
  - بعد «اعتماد نهائي» يُكتب `developerMode: false` في `settings.json`، ولا يمكن إعادته من الواجهة (فقط بتعديل الملف يدوياً).

### أ.5 دليل ربط النماذج داخل البرنامج
- قسم «دليل الربط» بخطوات مرقّمة لكل مزوّد: Claude و Gemini و Ollama على المكتبي وعلى الماك.
- **زر «اختبار الاتصال» لكل مزوّد**: يرسل سؤالاً قصيراً ويعرض النتيجة وسبب الفشل بالعربية.
- اقتراح نماذج Ollama حسب الجهاز:
  - **RTX 3090 (24GB):** نماذج حتى نحو 32 مليار معامل بضغط 4-bit.
  - **MacBook Air M5:** نماذج صغيرة ومتوسطة حسب الذاكرة المتاحة.
- نسخة نصية من الدليل في `docs/` للرجوع إليها.
- **المنفَّذ:** قسم «🔌 الربط» في الواجهة، و `POST /api/assistant/test` عبر `src/features/assistant/provider-tester.ts` (رسالة ثابتة بلا معلومات شخصية، حد رد صغير، حل مقترح بالعربية)، والدليل النصي [docs/08-AI-CONNECTION-GUIDE.md](08-AI-CONNECTION-GUIDE.md).

## المرحلة أ٢ — الذكاء عبر اشتراكاتك (بلا فواتير إضافية)

> **السبب:** مفاتيح API تُحاسَب برصيد منفصل عن اشتراكَي Claude Pro و Google Pro، وهذا غير مقبول. المطلوب أن يستخدم المساعد الاشتراكات المدفوعة أصلاً.

### ما تحقّقنا منه على الجهاز
- **Claude Code** يعمل دون واجهة (`claude -p`) باشتراك Pro، بعد تسجيل دخول لمرة واحدة يقوم به القائد (`claude auth login`). الاستهلاك من حصة الاشتراك نفسها (موافَق عليه).
- **Gemini CLI** رفضته Google برسالة صريحة توجّه الأفراد إلى Antigravity، و Antigravity بلا وضع تشغيل من برنامج آخر. لذلك يبقى Gemini عبر Antigravity والذاكرة المشتركة فقط.

### أ٢.1 مزوّد «Claude عبر الاشتراك» (`claude-cli`)
- `src/features/assistant/providers/claude-cli-provider.ts`: يشغّل Claude Code بلا shell، ويبثّ الرد من `stream-json`.
- **العزل والأمان:**
  - كل الأدوات مطفأة (`--tools ""`)، والأوامر والمهارات مطفأة.
  - لا خوادم MCP (`--strict-mcp-config` مع إعداد فارغ).
  - لا إعدادات مستخدم أو مشروع (`--setting-sources ""`).
  - لا حفظ للجلسات، والتشغيل في مجلد مؤقت فارغ يُحذف بعد الرد.
  - يتحقق البرنامج من رسالة البدء: إن ظهرت أي أداة أو خادم MCP يوقف التشغيل فوراً.
  - تُزال `ANTHROPIC_API_KEY` وما يشبهها من البيئة، حتى لا يتحول الاستخدام إلى فوترة API دون علمك.
- البحث عن البرنامج: مسار مخصص في الإعدادات، ثم `PATH`، ثم `~/.local/bin`، ثم النسخة المضمّنة في تطبيق Claude لسطح المكتب.
- النموذج: اسم مختصر مثل `sonnet` أو `opus` (افتراضياً `sonnet` لتوفير الحصة).

### أ٢.2 ترتيب المزوّدين الجديد
- **هجين (الافتراضي):** Claude عبر الاشتراك ← Ollama ← المعرفة المحلية.
- **سحابي:** Claude عبر الاشتراك فقط. **محلي:** Ollama فقط.
- **مفاتيح API:** خيار متقدم `apiKeysEnabled` مطفأ افتراضياً؛ عند تفعيله تُضاف Claude API و Gemini API بعد الاشتراك.

### أ٢.3 الواجهة والدليل
- بطاقة «Claude عبر اشتراكك» أولاً في قسم الربط: حالة التثبيت وتسجيل الدخول، وخطوات التسجيل لمرة واحدة، وزر «اختبار الاتصال».
- بطاقة Gemini تشرح أنه مربوط عبر Antigravity، ومفاتيح API تُنقل إلى قسم «متقدم».
- تحديث `docs/08-AI-CONNECTION-GUIDE.md`، واختبارات بمحاكي Claude Code وهمي (بلا اتصال حقيقي ولا استهلاك للحصة).

- **المنفَّذ (أ٢.1–أ٢.3):** `providers/claude-cli-provider.ts`، والترتيب الجديد في `provider-registry.ts`، وخيار `apiKeysEnabled` و `claudeCliModel` و `claudeCliPath` في الإعدادات، وواجهة الربط والإعدادات، واختبارات `tests/12-claude-subscription.test.ts` (59/59). متبقٍّ: تسجيل الدخول الحقيقي من القائد، ثم اختبار الاتصال الفعلي.

### أ٢.4 `ollama launch claude` — يُنفَّذ لاحقاً (بعد المرحلة د)
- يشغّل Ollama برنامج Claude Code نفسه على **نماذج Ollama** (المكتبي RTX 3090 أو المحلي) بدل خوادم Anthropic: مجاني بالكامل ولا يستهلك حصة Pro.
- **في البرنامج:** خيار لمزوّد `claude-cli` يوجّهه إلى Ollama (عنوان Ollama ونموذجه بدل الاشتراك)، فيصبح مسار التراجع: Claude بالاشتراك ← Claude Code على Ollama المكتبي ← Ollama مباشرة.
- **للعمل اليومي:** دليل لاستخدام `ollama launch claude` على المكتبي واللابتوب للبرمجة عند نفاد حصة Pro، مع ربطه بذاكرة Second Brain عبر MCP.
- يحتاج المرحلة د أولاً (الوصول إلى Ollama المكتبي عبر Cloudflare)، ويُختبر فعلياً على المكتبي.

## المرحلة ب — المثبّت والتشغيل التلقائي

- **مثبّت Windows** (`install-windows.ps1`) و**مثبّت الماك** (`install-macos.sh`). كل منهما:
  1. يتحقق من Node.js 24 أو يرشد لتثبيته.
  2. يسجّل **التشغيل التلقائي عند الدخول** دون نافذة: جدولة المهام في Windows، و LaunchAgent في الماك.
  3. ينشئ اختصاراً لفتح الواجهة.
  4. يسجّل خادم الذاكرة في Claude Code و Antigravity، مع نسخة احتياطية من ملفاتهما.
  5. يعطي اسماً لهذا الجهاز (مثل «Asus-Windows» و «MacBook-M5» و «Desktop-3090»).
- **مُلغٍ للتثبيت** يزيل التشغيل التلقائي والاختصار، ولا يمس البيانات.
- ملف تشغيل للماك بديل عن `.bat`، ومراجعة توافق المسارات والأوامر على macOS.
- **اختبار فعلي على الماك:** أطلب منك تشغيل المثبّت عليه وإرسال النتيجة.
- **المنفَّذ:**
  - مجلد `Second-Brain-System/install/`، وفيه `windows/` و `macos/`.
  - **Windows:** اختصار في مجلد بدء التشغيل يشغّل `start-hidden.vbs`، الذي يشغّل `run-server.ps1` مخفياً. المشغّل يعيد تشغيل الخادم عند التعطل (حتى 5 مرات خلال 10 دقائق) ويكتب السجل في `data/logs/server.log`.
    - اختير مجلد بدء التشغيل بدل جدولة المهام لأنه لا يحتاج صلاحيات مسؤول، ويظهر في «مدير المهام ← تطبيقات بدء التشغيل»، ويُعطَّل بنقرة.
  - **نافذة مستقلة:** `open-app.vbs` ثم `open-app.ps1`، فتُفتح الواجهة بوضع `--app` في Chrome أو Edge، مع أيقونة `install/second-brain.ico`.
  - **تسجيل خادم الذاكرة:** المثبّت يفحصه ويعرض حالته فقط، ولا يعدّل ملفات Claude Code أو Antigravity.
  - **الماك:** LaunchAgent بـ `RunAtLoad` و `KeepAlive`، و«Second Brain.command» على سطح المكتب.
  - **الاختبارات:** `tests/14-installer.test.ts`.
- **تجربة الماك:** تُنفَّذ في جلسة على الـ MacBook حسب [`docs/09-MAC-SETUP-HANDOFF.md`](09-MAC-SETUP-HANDOFF.md)، ثم نعود إلى Windows للمرحلة ج.

## المرحلة ج — المزامنة بين الأجهزة عبر Google Drive

### الفكرة
كل جهاز يعمل محلياً بالكامل. يُستخدم Google Drive عبر برنامجه على الكمبيوتر (Drive for desktop) كمجلد مزامنة يحوي:

```text
📁 <Google Drive>/Second-Brain-Sync/
├── 📄 manifest.json             # رقم آخر إصدار، الجهاز الذي نشره، وقته، وبصمته
├── 📄 write-lease.json          # الجهاز الذي يحمل صلاحية الكتابة الآن + آخر إشارة حياة
├── 📁 snapshots/                # آخر 10 نسخ مشفرة (Second-Brain-Snapshot-<إصدار>.enc.json)
└── 📁 devices/                  # ملف حالة لكل جهاز (آخر ظهور، الإصدار، Ollama، RustDesk ID)
```

### القواعد
1. **قفل الكتابة:** جهاز واحد فقط يكتب. الأجهزة الأخرى في **وضع القراءة**، مع شريط واضح «الكتابة الآن على Asus-Windows».
2. **نقل الصلاحية:** زر «انقل الكتابة إلى هذا الجهاز». يأخذ الجهاز آخر نسخة أولاً ثم يتسلّم القفل. إن لم يرسل حامل القفل إشارة حياة لمدة 30 دقيقة، يُعتبر القفل منتهياً.
3. **النشر:** حامل القفل ينشر نسخة مشفرة بعد كل تغيير (بتأخير دقيقتين لتجميع التغييرات) وعند الإغلاق. يرفض النشر إن وجد على Drive إصداراً أحدث من الذي بدأ منه، وهذه طبقة حماية ثانية.
4. **عند الإقلاع:** يقارن الجهاز إصداره بـ `manifest.json`. إن وجد نسخة أحدث يستوردها، بعد حفظ نسخته الحالية محلياً للاحتياط، ويخبرك بإشعار.
5. **التشفير:** النسخ مشفرة بمفتاح بيانات الخزنة، فـ Google لا يرى أي محتوى، وتُفتح بكلمة المرور أو بمفتاح الطوارئ.

### نقطة تصميم مهمة: مسارات المشاريع تختلف بين الأجهزة
مشروعك على Windows في `D:\Projects\MyApp`، وعلى الماك في `/Users/.../Projects/MyApp`. لذلك:
- بيانات المشروع **مشتركة**: الاسم، والوصف، والدخل، والفواتير، والذاكرة.
- **المسار يُحفظ لكل جهاز على حدة**.
- على جهاز لا يعرف مسار المشروع، يظهر المشروع بعلامة «غير موجود على هذا الجهاز» مع زر «حدّد مكانه».
- الإعدادات الخاصة بالجهاز (اسمه، ومسار Drive، وعناوين Ollama) **لا تُزامَن**.

### الاختبارات
محاكاة 3 أجهزة في مجلدات مؤقتة ومجلد Drive وهمي:
- النشر والاستيراد.
- رفض الكتابة دون قفل.
- نقل القفل وانتهاؤه.
- رفض النشر فوق إصدار أحدث.
- اختلاف مسارات المشاريع بين الأجهزة.

## المرحلة د — Ollama الموزّع

- **على المكتبي:** Ollama + `cloudflared` ينشر نطاقاً مثل `ollama.نطاقك.com`، محمياً بـ **Cloudflare Access Service Token**، فلا يصل أحد غير أجهزتك. أكتب لك الخطوات التفصيلية مع لقطات الإعداد.
- **في البرنامج:** قائمة عناوين Ollama مرتبة (المكتبي ثم المحلي). يُتجاوز العنوان غير المتاح خلال ثانيتين.
- **رموز Cloudflare Access** (Client ID و Secret) تُحفظ **داخل الخزنة** كأي مفتاح API.
- **تعديل قيد الأمان:** عنوان Ollama مسموح حالياً على الجهاز نفسه فقط. يُوسَّع ليقبل عناوين `https` المحمية برموز Access، وعناوين الشبكة المنزلية الخاصة.
- **سطر حالة المزوّدين** يعرض أي Ollama أجاب: «Ollama (المكتبي)» أو «Ollama (هذا الجهاز)».

## المرحلة هـ — صفحة «أجهزتي» والتحكم والتشغيل عن بُعد

- **لكل جهاز:**
  - متصل أو منفصل، وآخر ظهور.
  - صلاحية الكتابة.
  - رقم الإصدار.
  - Ollama ونماذجه.
  - زر **«اتصل بهذا الجهاز»** يفتح RustDesk على معرّف ذلك الجهاز.
- **مصدر البيانات:** ملفات حالة الأجهزة على Drive، فلا يلزم أي اتصال مباشر بين الأجهزة.
- **Wake-on-LAN للمكتبي:**
  - دليل تفعيله من BIOS و Windows لجهازك.
  - زر «شغّل المكتبي» يرسل الإشارة **حين تكون على الشبكة المنزلية نفسها**.
  - **من خارج المنزل** يحتاج الأمر جهازاً يبقى مشغّلاً في البيت ويستقبل الطلب. الخيارات مرتبة من الأبسط: ميزة الراوتر إن كان يدعمها، أو مقبس ذكي مع إعداد BIOS «التشغيل عند عودة الكهرباء»، أو جهاز صغير دائم التشغيل (Raspberry Pi). نحدد الخيار بعد معرفة نوع الراوتر.
- **دليل RustDesk:** التثبيت على الأجهزة الثلاثة، وكلمة مرور دائمة قوية، والمصادقة الثنائية، والسماح لأجهزتك فقط، والخادم الوسيط الخاص كخيار لاحق.

## المرحلة و — المستقبل (مؤجَّلة)

- **تطبيق الجوال:** يبدأ تطبيق ويب قابلاً للتثبيت (PWA) يقرأ آخر نسخة مشفرة ويفكّها على الجوال نفسه. التطبيق الأصلي لأندرويد يأتي لاحقاً عند الحاجة لميزات خاصة.
- **المصادقة الثنائية للعائلة:**
  - رمز Google Authenticator **اختياري** عند فتح وضع العائلة على الجهاز.
  - **رموز احتياطية مطبوعة في الكتيب** حتى لا تُقفل زوجتك خارج كل شيء إن ضاع الهاتف.
  - **باركود QR** لمفتاح الطوارئ في الكتيب لإدخاله بالكاميرا.
