## 1. ما هو Second Brain؟ وما هدفه؟

**Second Brain** (العقل الثاني) نظام شخصي يعمل على أجهزة القائد، ويجمع في مكان واحد كل ما يحتاجه لإدارة حياته الرقمية ومشاريعه البرمجية، ولحماية عائلته إن غاب.

### المشكلة التي يحلّها
- **الأسرار مبعثرة:** كلمات المرور، والإيميلات، وأكواد الاسترداد، ومفاتيح API، وملفات التوقيع (`keystore`)، وملفات `.env`، موزّعة بين أجهزة وملفات وذاكرة شخص واحد.
- **المشاريع متعددة:** لكل مشروع أوامر تشغيل، واستضافة، وفواتير، ودخل، وملفات حساسة، ولا يوجد سجل واحد يجمعها.
- **أدوات الذكاء بلا ذاكرة مشتركة:** Claude Code و Antigravity لا يعرف أحدهما ما قرره الآخر، ولا يعرفان صاحب المشاريع.
- **العائلة لا تعرف ماذا تفعل** إن تعطّل الحاسوب أو غاب القائد: أين الحسابات؟ أي المشاريع تدرّ دخلاً؟ كيف تتعامل مع المبرمجين بأمان؟

### الهدف
1. **خزنة واحدة مشفرة** لكل الأسرار، تُفتح بكلمة مرور القائد، أو بمفتاح طوارئ مطبوع للعائلة.
2. **رادار للمشاريع** يفحصها ويوثّقها ويحمي ملفاتها الحساسة ويتابع تغيّرها.
3. **ذاكرة مشتركة** بين أدوات الذكاء، فيعرف كل وكيل ملف القائد وسياق المشروع والقرارات السابقة.
4. **مساعد ذكي بالعربية** يجيب عن المشاريع والحالة، بوضع للقائد ووضع مبسّط للعائلة، بلا فواتير إضافية.
5. **خطة طوارئ عائلية** كاملة: كتيب مطبوع، ونسخ احتياطية مشفرة تُستعاد حتى على جهاز جديد، ودليل مكتوب بلغة بسيطة.
6. **عمل على عدة أجهزة** (لابتوب، ماك، مكتبي قوي) مع مزامنة مشفرة.

### الفائدة باختصار
- **راحة البال:** كل شيء مرتب ومحمي ومنسوخ، والعائلة تعرف الطريق.
- **سرعة العمل:** يسأل القائد المساعد بدل البحث، وتعرف أدوات الذكاء السياق بدل إعادة الشرح.
- **أمان حقيقي:** تشفير عسكري، والبيانات لا تخرج من أجهزته إلا مشفرة.
- **لا اشتراكات جديدة:** يستعمل اشتراك Claude Pro الموجود، ونماذج محلية مجانية.

## 2. الفكرة العامة ومبادئ التصميم

| المبدأ | المعنى العملي |
| :--- | :--- |
| **محلي أولاً** | البرنامج خادم صغير على الجهاز نفسه (`127.0.0.1`)، والواجهة صفحة تُفتح في نافذة مستقلة. لا يوجد خادم مركزي، ولا يعتمد على الإنترنت ليعمل |
| **الخصوصية** | الأسرار لا تُكتب على القرص إلا مشفرة، ولا تُرسل لأي ذكاء اصطناعي. ما يخرج من الجهاز (المزامنة، النسخ) مشفر دائماً |
| **بلا حزم خارجية** | الكود مكتوب بـ Node.js 24 و TypeScript فقط، بلا أي حزمة npm، حتى يبقى يعمل بعد سنوات، ومن فلاشة USB |
| **العربية أولاً** | الواجهة، والرسائل، والأخطاء، والتعليقات داخل الكود، والوثائق، كلها بالعربية |
| **العائلة جزء من التصميم** | وضع عائلة مبسّط، ومفتاح طوارئ مطبوع، ودليل مكتوب لزوجة القائد |
| **لا فواتير إضافية** | الذكاء عبر اشتراك Claude Pro (Claude Code) أو Ollama المجاني. مفاتيح API خيار متقدم مطفأ |
| **كل شيء مختبر وموثّق** | أكثر من 80 فحصاً دائماً، وكل تغيير يرفع رقم الإصدار ويُوثَّق (الدستور) |

**الصورة الكاملة في جملة:** كل جهاز يشغّل Second Brain كاملاً وحده. الخزنة والمشاريع والذاكرة والمحادثات و Obsidian تنتقل بين الأجهزة بنسخ مشفرة عبر Google Drive. أدوات الذكاء (Claude Code و Antigravity) تتصل بذاكرته عبر MCP. والعائلة تستطيع الوصول إلى الضروري بمفتاح الطوارئ.

## 3. الأجهزة والبيئة الحالية

## 4. التشغيل

### 4.1 التثبيت (مرة واحدة لكل جهاز)
**Windows** (لا يحتاج صلاحيات مسؤول):
```powershell
powershell -ExecutionPolicy Bypass -File Second-Brain-System\install\windows\install-windows.ps1
```
- يعرض ما سيفعله أولاً، ويدعم `-Preview` للعرض فقط دون تغيير.
- **ينشئ ثلاثة اختصارات فقط:**
  - في مجلد «بدء التشغيل»: تشغيل مخفي عند تسجيل الدخول. يظهر في «مدير المهام ← تطبيقات بدء التشغيل»، ويُعطَّل من هناك.
  - على سطح المكتب وفي قائمة ابدأ: «Second Brain» بأيقونة الدماغ، يفتح النافذة المستقلة.
- **يكتب هوية الجهاز** في `data/device.json` بأداة مشتركة (`install/device-identity.ts`):
  - الملف غير موجود: تُكتب هوية جديدة.
  - موجود لنفس النظام: يبقى.
  - منقول من نظام آخر: يُحفظ نسخةً احتياطية ثم تُكتب هوية جديدة.
- يفحص تسجيل خادم الذاكرة في Claude Code و Antigravity ويعرض حالته فقط، ولا يعدّل إعداداتهما.

**الماك:**
```bash
bash Second-Brain-System/install/macos/install-macos.sh --device-name "MacBook-M5"
```
- **LaunchAgent** باسم `com.secondbrain.server`، بالخيارات:
  - `RunAtLoad`: يعمل عند تسجيل الدخول.
  - `KeepAlive`: يعود إن توقف.
  - `MaterializeDatalessFiles`: يسمح بتنزيل ملفات Google Drive الموجودة في السحابة فقط.
- **ملف «Second Brain.command»** على سطح المكتب لفتح النافذة.

### 4.2 كيف يعمل في الخلفية
- **Windows:** الاختصار يشغّل `start-hidden.vbs`، الذي يشغّل `run-server.ps1` مخفياً.
  - المشغّل يمنع تشغيل نسختين في الوقت نفسه.
  - يعيد تشغيل الخادم إن تعطّل، حتى 5 مرات خلال 10 دقائق، ثم يتوقف حتى لا يدور بلا نهاية.
  - يكتب السجل في `data/logs/server.log`.
- **الخادم** يستمع على `127.0.0.1:4777`، أي هذا الجهاز فقط. عند بدئه:
  - يشغّل المراقب الدوري للمشاريع.
  - يبدأ تحميل الصوت عالي الجودة.
  - يبدأ دورة المزامنة كل دقيقتين.

### 4.3 النافذة المستقلة
اختصار «Second Brain» يشغّل `open-app.ps1`:
1. يتأكد أن الخادم يعمل، ويشغّله إن لم يكن.
2. يفتح الواجهة في **Chrome أو Edge بوضع `--app`**: نافذة خاصة بلا شريط عنوان أو تبويبات، بأيقونة البرنامج في شريط المهام.

### 4.4 التشغيل اليدوي (بديل بلا تثبيت)
- `Launch-Second-Brain.bat` في جذر المشروع، يعمل من أي قرص أو فلاشة. يفتح المتصفح بعد جاهزية الخادم، ويُغلق الخادم بإغلاق نافذته.
- أو من داخل `Second-Brain-System`:
  ```bash
  node src/features/dashboard-app/desktop-server.ts
  ```

### 4.5 الإيقاف والإزالة
```powershell
powershell -ExecutionPolicy Bypass -File Second-Brain-System\install\windows\uninstall-windows.ps1
```
- يحذف الاختصارات الثلاثة، ويوقف المشغّل والخادم.
- **لا يمس أي بيانات:** الخزنة، والمحادثات، والإعدادات، والأصوات تبقى كما هي.
- على الماك: `bash Second-Brain-System/install/macos/uninstall-macos.sh`.

### 4.6 بعد كل تحديث (`git pull`)
**يجب إعادة تشغيل الخادم**، وإلا يبقى يعمل بالكود القديم. انتبه: `/api/health` يعرض الإصدار الجديد مع ذلك، لأنه يقرأ الرقم من `package.json` في كل طلب.
- **Windows:** أوقف عملية `node` الخاصة بالخادم، فيعيدها المشغّل تلقائياً، أو سجّل الخروج ثم الدخول.
- **الماك:** `launchctl kickstart -k gui/$(id -u)/com.secondbrain.server`.

## 5. الواجهة: كل قسم وما يفعله

**الشريط العلوي:**
- شعار الدماغ، واسم البرنامج.
- مؤشرات سريعة: عدد المشاريع، وحالة الخزنة، وعدد سجلات الذاكرة.
- زرا التبديل: «غرفة القيادة» و«وضع العائلة».

**القائمة الجانبية:** القيادة، المشاريع، الخزنة، الذاكرة، الطوارئ، الربط، المزامنة، الإعدادات.

| القسم | ما فيه |
| :--- | :--- |
| **🎙️ القيادة** | **النواة:** موجة متحركة تنبض مع كتابة الرد ونطقه. **المحادثة مع المساعد:** إرسال، وإدخال بالصوت، ونطق آخر رد، وزر «الرد الصوتي: يعمل/متوقف»، و«المحادثات المحفوظة»، و«محادثة جديدة». **سطر المزوّدين** يعرض الترتيب، وأيها متاح ✓ أو غير متاح ✗ |
| **📡 المشاريع** | بطاقة لكل مشروع: التقنيات، والفرع، وحالة تأمين الملفات الحساسة، وتحذير إن رُفع ملف حساس على Git، وأمر التشغيل، وآخر commit. زر «مشروع جديد» |
| **صفحة المشروع** | تُفتح بالضغط على بطاقته. فيها: ما هو المشروع، وخلاصة يولّدها الذكاء أو تُكتب يدوياً، والأوامر مع زر نسخ، وحالة Git، والملفات الحساسة، وسجل التغييرات، والقرارات من الذاكرة، والمحادثات المؤرشفة. وأزرار: فتح المجلد، فتح في VS Code، إعادة الفحص، «📍 مكانه على هذا الجهاز»، تعديل، إيقاف المراقبة |
| **🔐 الخزنة** | فتح بكلمة المرور أو مفتاح الطوارئ. بطاقات الأسرار بفئات (إيميل، كلمة مرور، مفتاح API، كود استرداد، فواتير)، والقيمة مخفية حتى تُكشف. ملاحظات للقائد وملاحظات للعائلة. ومفاتيح API في قسم متقدم |
| **🧠 الذاكرة** | سجلات الذاكرة المشتركة (من Claude Code و Antigravity والمساعد)، وزر سحب المحادثات المؤرشفة يدوياً |
| **🛡️ الطوارئ** | كتيب الطوارئ للطباعة، والنسخ الاحتياطية المشفرة (إنشاء وسرد)، والاستعادة إلى مجلد جديد |
| **🔌 الربط** | بطاقة «Claude عبر اشتراكك» مع خطوات التسجيل وزر الاختبار. وشرح Gemini عبر Antigravity. وبطاقة Ollama مع اقتراح نماذج لكل جهاز. وبطاقة «🔊 الصوت العربي» لحالته واختيار الصوت وتجربته وتنزيله. ومفاتيح API (متقدم). وشرح ربط الذاكرة بـ MCP |
| **🔄 المزامنة** | حالة الجهاز: كاتب أو قارئ، وإصداره، وآخر إصدار منشور ومن نشره، والتغييرات غير المنشورة، وآخر استيراد ونشر. وأزرار: انقل الكتابة، انشر الآن، اترك الكتابة، استورد الأحدث. وإعداد المجلد مع اقتراح مجلد Google Drive تلقائياً |
| **⚙️ الإعدادات** | تطلب كلمة المرور الرئيسية في كل مرة (صلاحية 5 دقائق). فيها: الهوية، والذكاء (الوضع، ونموذج Claude عبر الاشتراك، ومسار Claude Code، ومتقدم: مفاتيح API ونماذجها، ونموذج Ollama وعنوانه)، والصوت، والموصلات والمراقب، والأمان والنسخ (القفل التلقائي، وعدد النسخ، ومجلد النسخ الإضافي)، ومنطقة الخطر في وضع التطوير |
| **❤️ وضع العائلة** | واجهة مبسطة بخط كبير: سؤال المساعد بلغة بسيطة، و«استمعي»، و«المحادثات السابقة»، والمشاريع بملخص مفهوم. تُفتح بمفتاح الطوارئ، ولا تصل إلى أدوات القائد |

**شريط وضع القراءة:** يظهر أعلى الصفحة على الجهاز الذي لا يحمل صلاحية الكتابة، ويقول أين الكتابة الآن.

## 6. الميزات بالتفصيل

### 6.1 الخزنة المشفرة
**الملف:** `src/features/vault/vault-manager.ts`، والتشفير في `src/core/crypto-engine.ts`.

- **التشفير:** AES-256-GCM. هذا تشفير مع توقيع مصادقة، فأي تعديل على الملف يُكتشف ويُرفض.
- **مفتاح البيانات (DEK):** مفتاح عشوائي طوله 256 بت يشفّر محتوى الخزنة. هذا المفتاح نفسه **مغلَّف مرتين**:
  - بكلمة المرور الرئيسية (`commanderWrap`).
  - بمفتاح الطوارئ العائلي (`emergencyWrap`).
  - أي أن تغيير كلمة المرور لا يعيد تشفير البيانات، بل يعيد تغليف المفتاح فقط.
- **اشتقاق المفتاح من كلمة المرور:** scrypt بمعاملات `N=131072, r=8, p=1`. هذا يجعل تخمين كلمة المرور بطيئاً جداً.
- **كلمة المرور الرئيسية:** 10 أحرف على الأقل.
- **مفتاح الطوارئ:** 128 بت، بصيغة `SB-XXXX-XXXX-…-XXXX-CCCC`: ثماني مجموعات، ثم مجموعة تحقق أخيرة تكشف أي خطأ عند كتابته يدوياً. يظهر **مرة واحدة فقط** عند الإنشاء، ثم يُطبع في الكتيب. يمكن تدويره، فيبطل المفتاح القديم.
- **الحفظ ذرّي:** يُكتب ملف مؤقت ثم يُستبدل، مع خمس نسخ سابقة (`.bak-1` … `.bak-5`)، فلا يتلف الملف إن انقطع الكهرباء.
- **الخزنة لا تُمسح أبداً:** الإنشاء يرفض العمل فوق خزنة موجودة.
- **الجلسة:**
  - فتح الخزنة ينشئ جلسة بكوكي آمن.
  - **قفل تلقائي** بعد 10 دقائق بلا نشاط (قابل للتغيير).
  - المحاولات الخاطئة تُبطئ المحاولة التالية تصاعدياً، حتى 5 دقائق.
- **مستويا الوصول:**
  - **القائد** (كلمة المرور): كل شيء.
  - **العائلة** (مفتاح الطوارئ): القراءة ووضع العائلة. لا إعدادات، ولا تعديل، ولا أدوات خطرة.
- **الملفات الحساسة للمشاريع** (`.env`، keystore…) تُنسخ مشفرة داخل الخزنة (حتى 5MB للملف)، وتُستعاد عند الحاجة.

  - **الملاحظات اليدوية داخل هذه الملفات محمية** من الكتابة فوقها.
- **المراقب الدوري** (`project-watcher.ts`): كل 15 دقيقة يعيد فحص المشاريع ويسحب المحادثات المؤرشفة. يتوقف في وضع القراءة.

### 6.3 الذاكرة المشتركة وخادم MCP
**الملفات:** `src/features/ai-memory/`، و `src/tools/mcp-memory-server.ts`

- **الذاكرة المشتركة** (`data/ai-memory-store.json` ونسخة في Obsidian): سجلات «ماذا أُنجز وما القرارات»، من أي أداة ذكاء، مربوطة بمشروع. **الأسرار تُحذف تلقائياً** قبل الحفظ.
- **خادم MCP** (بروتوكول Model Context Protocol عبر stdio): تشغّله أدوات الذكاء نفسها، وفيه 6 أدوات:

| الأداة | ماذا تفعل |
| :--- | :--- |
| `second_brain_get_commander_profile` | ملف القائد: من هو وأسلوبه ومعاييره |
| `second_brain_get_commander_and_projects_context` | الملف + ملخص كل المشاريع |
| `second_brain_get_project_context` | سياق مشروع واحد بالتفصيل |
| `second_brain_recall_shared_memory` | استرجاع قرارات مشروع |
| `second_brain_search_memory` | البحث في الذاكرة |
| `second_brain_record_shared_memory` | تسجيل ملخص عمل وقرارات (يُرفض في وضع القراءة) |

- **مسجّل في:** Claude Code (`~/.claude.json`) و Antigravity (`~/.gemini/antigravity/mcp_config.json`) على Windows. على الماك يُسجَّل يدوياً حسب `docs/08`.
- **أرشفة المحادثات** (`transcript-harvester.ts` والموصلات):
  - يقرأ سجلات Claude Code (`~/.claude/projects`) و Antigravity (`~/.gemini/antigravity/brain`).
  - يحذف الأسرار، ويحفظها في Obsidian داخل مجلد المشروع المعني (`AI-Conversations`) أو في `03-AI-Shared-Memory/*-Sessions`.
  - **تزايدي:** لا يعيد ما لم يتغير.
  - جلسات الوكلاء الفرعيين الداخلية في Antigravity (رسائل نظام بلا سؤال من القائد) تُتجاهل عمداً.

### 6.8 المزامنة بين الأجهزة
**الملفات:** `src/features/sync/`، والتصميم في [`docs/07`](07-EXPANSION-PLAN.md) (المرحلة ج)

- **الفكرة:** كل جهاز يعمل محلياً، وتنتقل البيانات بنسخ **مشفّرة بمفتاح الخزنة** عبر مجلد مُزامَن. لا يرى Google أي محتوى.
- **المجلد المعتمد:** `My Drive/Second Brain/` (على الماك العربي «ملفاتي/Second Brain»)، وفيه:
  ```text
  Second-Brain-Sync/
  ├── manifest.json        ← رقم آخر إصدار، ومن نشره، وبصمته
  ├── write-lease.json     ← الجهاز الذي يحمل صلاحية الكتابة + آخر إشارة حياة
  ├── snapshots/           ← آخر 10 نسخ مشفرة (Second-Brain-Snapshot-000004-MacBook-M5.enc.json)
  └── devices/             ← ملف حالة لكل جهاز (آخر ظهور، الإصدار)
  Backups/                 ← نسخ الطوارئ الإضافية
  ```
- **ما يُزامَن:**
  - الخزنة، والهوية، وقائمة المشاريع.
  - الذاكرة، والمحادثات.
  - Obsidian، ما عدا ملفات واجهته `workspace*.json` و `.trash`.
- **ما لا يُزامَن:**
  - إعدادات كل جهاز: الذكاء، والصوت، والمجلد، والأمان.
  - هويته، ومسارات مشاريعه.
  - حالة الأرشفة والفحص، والسجلات، والنسخ المحلية، و `vendor/`.
- **قفل الكتابة:**
  - جهاز واحد يكتب، ويرسل إشارة حياة كل دقيقتين، وينتهي قفله بعد 30 دقيقة بلا إشارة.
  - النقل يدوي. وإن كان القفل نشطاً عند جهاز آخر يتطلب تأكيداً صريحاً.
  - «اترك الكتابة» ينشر آخر التغييرات أولاً.
- **الاستيراد عند فتح الخزنة**، لأن فك النسخة يحتاج مفتاحها:
  1. يتحقق من التشفير والبصمة.
  2. يحفظ نسخة احتياطية مشفرة من الحالة المحلية (`data/sync-backups/`، آخر 5).
  3. يطبّق النسخة بمطابقة تامة لـ Obsidian والمحادثات.
  4. ينسى سجل الأرشفة لما حُذف، فيُعاد أرشفته.
- **النشر:**
  - كل دقيقتين إن تغيّر المحتوى، والخزنة مفتوحة، والجهاز حامل الكتابة. وعند قفل الخزنة. وبزر «انشر الآن».
  - يُرفض النشر فوق إصدار أحدث من أساس الجهاز.
- **الحمايات:**
  - يُرفض الاستيراد إن كانت النسخة من خزنة مختلفة، أو بصمتها لا تطابق محتواها، أو ملفها لم يكتمل تنزيله.
  - «تعذّرت القراءة» لا تعني «غير موجود»: أي ملف غير مقروء يوقف العملية برسالة عربية.
  - «أول جهاز» يُقرَّر فقط إن لم يوجد manifest ولا أي نسخة.
- **وضع القراءة** على غير حامل الكتابة:
  - 14 مساراً تعدّل البيانات المشتركة تُرفض برمز 423 مع السبب.
  - المحادثات لا تُحفظ.
  - المراقب متوقف.
  - MCP يرفض تسجيل الذاكرة.
- **حدّ معروف:** النشر يحتاج الخزنة مفتوحة، فما يكتبه المراقب والخزنة مقفلة ينتظر حتى تُفتح.
- **طريقة الاستخدام اليومية:** تعمل على جهاز ← قبل تركه «اترك الكتابة» ← على الجهاز الآخر افتح الخزنة (يُستورد تلقائياً) ← «انقل الكتابة إلى هذا الجهاز».

## 7. الأمان والخصوصية

### 7.1 طبقات الحماية في الخادم
- **الاستماع:** على `127.0.0.1` فقط، فلا يصل إليه أي جهاز آخر في الشبكة.
- **حماية الطلبات:**
  - **Host / Origin:** أي طلب من مصدر غير واجهة البرنامج يُرفض (حماية من CSRF ومن DNS rebinding).
  - **JSON فقط:** طلبات الكتابة تقبل `application/json` فقط، وبحد أقصى 1MB للطلب.
  - **جلسة الخزنة:** في كوكي `HttpOnly`، وتنتهي بالقفل التلقائي.
- **سياسة أمان المحتوى (CSP) الصارمة:** لا سكربتات ولا أنماط مضمّنة، ولا تحميل من أي موقع خارجي. الصوت المولّد يُشغَّل من `blob:` فقط.
- **كل نص في الواجهة** يُعرض عبر `textContent`، فلا يمكن حقن HTML (XSS).
- **الصلاحيات:** مسارات للقائد فقط (`commanderOnly`)، ومسارات تتطلب الخزنة (`requiresSession`)، ومسارات بيانات مشتركة (`sharedWrite`) تُرفض في وضع القراءة.

### 7.2 ماذا يخرج من الجهاز؟
| ما يخرج | إلى أين | كيف |
| :--- | :--- | :--- |
| سؤالك وسياق المشاريع (بلا أسرار ولا خزنة) | Anthropic، عبر Claude Code باشتراكك | فقط إن كان Claude المزوّد المستخدم |
| نسخ المزامنة | Google Drive | **مشفرة بمفتاح الخزنة**؛ Google لا يرى المحتوى |
| نسخ الطوارئ الإضافية | Google Drive | **مشفرة** |
| الكود والوثائق | GitHub (عام) | بعد فحص لكل commit بحثاً عن بريد أو أسرار أو بيانات شخصية |

**ما لا يخرج أبداً:**
- محتوى الخزنة لأي ذكاء اصطناعي.
- الصوت، فيُولَّد محلياً.
- Ollama والمعرفة المحلية، فهما محليان بالكامل.
- مجلد `data/` و `vendor/` والإعدادات الحقيقية إلى GitHub.

### 7.3 قواعد ملزمة (من الدستور)
1. الخزنة لا تُمسح ولا تُعاد تهيئتها أبداً.
2. لا يُكتب سر على القرص بنص مكشوف.
3. الأسرار تُحذف تلقائياً من المحادثات المؤرشفة والذاكرة وسياق المساعد.
4. تسجيل الدخول لأي حساب يقوم به القائد بنفسه.
5. أي تعديل على إعدادات برامج أخرى يُعرض أولاً مع نسخة احتياطية.
6. الرفع إلى GitHub بموافقة القائد الصريحة فقط.

## 9. البنية البرمجية

### 9.1 التقنيات
- **Node.js 24+** يشغّل ملفات TypeScript مباشرة، بلا بناء ولا حزم npm.
- **الوحدات المدمجة فقط:** `node:http` و `node:crypto` و `node:fs` و `child_process`…

| **النسخة (Snapshot)** | ملف مشفر فيه كل البيانات المشتركة بإصدار معيّن، للمزامنة |
| **manifest.json** | ملف يشير إلى أحدث نسخة على مجلد المزامنة |
| **قفل الكتابة (Lease)** | من يحق له تعديل البيانات المشتركة الآن |
| **وضع القراءة** | حالة الجهاز الذي لا يحمل قفل الكتابة |
| **إشارة الحياة (Heartbeat)** | تحديث دوري يثبت أن حامل القفل ما زال يعمل |
| **المطابقة التامة** | عند الاستيراد يصبح المجلد مطابقاً للنسخة، بما في ذلك حذف ما حُذف |
| **LaunchAgent** | آلية macOS لتشغيل برنامج تلقائياً عند الدخول |
| **وضع `--app`** | فتح صفحة في نافذة متصفح بلا شريط عنوان، كأنها برنامج |
| **وضع التطوير** | يسمح بالتصفير أثناء البناء، ويُطفأ عند الاعتماد النهائي |
