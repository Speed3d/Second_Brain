# 10 — تسليم العودة إلى Windows: ما حدث على الماك وما يجب فعله الآن

> **لمن هذا الملف؟** للقائد، ولجلسة Claude Code على Windows التي لا تملك سياق جلسة الماك.
> **يا Claude على Windows:** اقرأ هذا الملف كاملاً أولاً، ثم [`CONSTITUTION-AND-RULES.md`](../CONSTITUTION-AND-RULES.md)، ثم [`CHANGELOG.md`](../CHANGELOG.md) (القسمان 1.8.3 و 1.8.4)، ثم [`docs/07-EXPANSION-PLAN.md`](07-EXPANSION-PLAN.md) (المرحلة ج). نفّذ القسم 4 بالترتيب، وحدّث سجل التنفيذ في القسم 8.
> **كُتب في:** 2026-11-15 على الماك، عند الإصدار **1.8.4** (الوسم `v1.8.4`).
> **السجل الكامل لجلسة الماك:** [`docs/09-MAC-SETUP-HANDOFF.md`](09-MAC-SETUP-HANDOFF.md) (القسم 8).

## 1. الخلاصة في سطور

- **المرحلة ب اكتملت على الماك واختُبرت بالكامل.** نجحت كل بنود الخطوات 1–7 في `docs/09`.
- **اكتُشفت مشكلتان حقيقيتان وأُصلحتا:**
  - **1.8.3:** هوية الجهاز المنقولة من نظام آخر.
  - **1.8.4:** حزمة Piper الرسمية للماك معطوبة.
- **الصوت الرئيسي على الماك هو XTTS-v2** (كما في Windows)، والاحتياطي صوت النظام «Majed».
- **Claude عبر الاشتراك يعمل على الماك** من خادم الخلفية.
- **الاختبارات على الماك:** 71/71. **على Windows لم تُشغَّل بعد بالإصدار 1.8.4.**
- **تعديل واحد على Windows لم يُجرَّب:** `install/windows/install-windows.ps1`. يجب تجربته أولاً (القسم 4).

## 2. ما تغيّر في الكود (يصل إلى Windows عبر `git pull`)

### 2.1 الإصدار 1.8.3 — هوية الجهاز
| الملف | التغيير |
| :--- | :--- |
| `Second-Brain-System/install/device-identity.ts` | **جديد.** أداة مشتركة يستدعيها المثبّتان. تقرر ما يُفعل بـ `data/device.json` |
| `Second-Brain-System/install/macos/install-macos.sh` | يستدعي الأداة. المعاينة تعرض القرار بدقة. الهوية تُكتب **قبل** تشغيل الخادم |
| `Second-Brain-System/install/windows/install-windows.ps1` | يستدعي الأداة بدل الكود المضمّن القديم (في المعاينة وفي التثبيت). **لم يُشغَّل على Windows بعد** |
| `Second-Brain-System/tests/14-installer.test.ts` | اختبار جديد للهوية في مجلد مؤقت |

**منطق الأداة:**
- `data/device.json` غير موجود ← تُكتب هوية جديدة لهذا الجهاز.
- موجود ولنفس النظام (`platform` = `windows` على Windows) ← **يبقى كما هو**.
- موجود لنظام آخر، أو تالف ← يُنقل إلى `data/device.<النظام>.json.bak` (دون الكتابة فوق نسخة سابقة)، ثم تُكتب هوية جديدة. **لا يُحذف أي شيء.**

**المشكلة التي أصلحتها:** نُقل المجلد من Windows إلى الماك ومعه `data/device.json` بهوية Windows. المثبّت القديم كان يُبقي أي ملف موجود، فكان الماك سيحمل هوية Windows نفسها. هذا يكسر المزامنة في المرحلة ج، لأن الجهازين سيظهران كجهاز واحد.

**المتوقع على Windows:** ملفك الحالي `platform: windows`، فيبقى كما هو. ستظهر رسالة «هوية الجهاز موجودة مسبقاً لهذا الجهاز … (لم تتغير)».

### 2.2 الإصدار 1.8.4 — الصوت العربي على الماك
| الملف | التغيير |
| :--- | :--- |
| `Second-Brain-System/src/features/voice/tts-service.ts` | دالة جديدة `probePiper()` تشغّل `piper --version` قبل اختيار Piper (مرة كل دقيقة على الأكثر). إن فشل لا يُختار، ويُستخدم صوت النظام، ويظهر السبب بالعربية |
| `Second-Brain-System/src/tools/install-arabic-voice.ts` | على الماك لا يُنزَّل شيء: يتحقق من صوت النظام العربي (Majed) أو يشرح طريقة إضافته. على Windows لم يتغيّر التنزيل. الدالة تعيد الآن `{ messageAr }` |
| `Second-Brain-System/src/features/dashboard-app/routes/voice-routes.ts` | يعرض رسالة المثبّت الفعلية |
| `Second-Brain-System/src/features/dashboard-app/public/app.js` | زر «تنزيل الصوت العربي المدمج» يختفي حين يكون صوت الماك مستخدماً |
| `Second-Brain-System/tests/13-conversations-and-voice.test.ts` | اختبار Piper المعطوب، واختبار أن مثبّت الماك لا ينزّل شيئاً. محاكي Piper صار يجيب على `--version` |

**المشكلة:** الحزمة `piper_macos_aarch64.tar.gz` (إصدار `2023.11.14-2`) فيها ملف تنفيذي **x86_64** تنقصه `libespeak-ng.1.dylib`، فيفشل بخطأ `dyld`. والكود القديم كان يختار Piper لمجرد وجود ملفه، فيفشل كل طلب صوت.

**أثر ذلك على Windows:**
- `probePiper()` سيشغّل `piper.exe --version`. **يجب التأكد أن Kareem ما زال يُختار احتياطياً على Windows** (القسم 4، الخطوة 4).
- إن فشل `--version` على Windows لأي سبب، لن يُختار Piper. سيظهر السبب في «🔌 الربط ← 🔊 الصوت العربي»، وعندها أصلح `probePiper()`.

## 4. الخطوات على Windows بالترتيب

كل الأوامر من داخل مجلد المشروع على Windows.

### الخطوة 1 — السحب
```powershell
git status
git pull
git log --oneline -3
```
- **المتوقع:** آخر commit هو `v1.8.4: …`، والوسم `v1.8.4` موجود (`git tag --sort=-v:refname`).
- **تنبيه نهايات الأسطر:** الملفات على Windows بنهايات CRLF في مجلد العمل وبـ LF في المستودع، فهذا طبيعي. إن ظهرت عشرات الملفات «معدّلة» بلا تغيير فعلي، تحقّق بـ `git diff --ignore-cr-at-eol --stat`. إن كان فارغاً فالفرق نهايات أسطر فقط. هذا ما حدث على الماك بعد النقل.
- **لا تنسخ `data/` من الماك إلى Windows.** البيانات على الجهازين منفصلة الآن (انظر القسم 5).

### الخطوة 2 — الاختبارات
```powershell
cd Second-Brain-System
node tests/run-all-tests.ts
```
- **المتوقع:** نجاح كل الحزم، ونحو **72 فحصاً** (71 على الماك + فحص معاينة Windows الذي يُتخطى على الماك).
- **انتبه خصوصاً إلى:**
  - **الحزمة 14:** صياغة `install-windows.ps1` مع UTF-8 BOM، ومعاينة مثبّت Windows.
  - **الحزمة 13:** Piper المعطوب، ومثبّت الماك. على Windows، `installArabicVoice(…, 'darwin')` يجب أن يرفض برسالة Majed لأن `say` غير موجود، وهذا مكتوب في الاختبار.

### الخطوة 3 — مثبّت Windows (التعديل الوحيد غير المجرَّب)
```powershell
powershell -ExecutionPolicy Bypass -File install\windows\install-windows.ps1 -Preview
```
- **المتوقع:** سطر «✔ هوية الجهاز موجودة مسبقاً لهذا الجهاز «DESKTOP-…» (لم تتغير)» ثم «وضع المعاينة: لم يُغيَّر أي شيء.»
- **إن ظهرت العربية مشوّهة:** المشكلة في ترميز الطرفية لمخرجات Node، وليست في الملف. `install-windows.ps1` يضبط `[Console]::OutputEncoding` على UTF-8.
- ثم أعد التثبيت الفعلي (بموافقة القائد) حتى يُجرَّب الاستدعاء الحقيقي:
  ```powershell
  powershell -ExecutionPolicy Bypass -File install\windows\install-windows.ps1
  ```
  - **المتوقع:** الهوية لم تتغير (نفس `deviceId` في `data\device.json`)، والخادم يعمل.
  - **تحقّق:** `curl.exe -s http://127.0.0.1:4777/api/health` يرد بـ `"version":"1.8.4"`.

### الخطوة 4 — الصوت على Windows بعد 1.8.4
1. أعد تشغيل الخادم (أو سجّل الخروج ثم الدخول) حتى يعمل بالكود الجديد.
2. افتح «🔌 الربط ← 🔊 الصوت العربي». **المتوقع:** «XTTS-v2 (عالي الجودة)»، والمحرك الاحتياطي **Kareem (piper)** لا صوت Windows.
3. إن ظهر الاحتياطي «صوت Windows العربي» بدل Kareem، فـ `piper.exe --version` فشل. شغّله يدوياً:
   ```powershell
   Second-Brain-System\vendor\piper\piper.exe --version
   ```
   ثم أصلح `probePiper()` في `src/features/voice/tts-service.ts` (مثلاً بقبول مخرجات الإصدار)، وارفع الإصدار إلى 1.8.5.
4. جرّب «تجربة الصوت».

### الخطوة 5 — تحديث التوثيق والرفع
- حدّث القسم 8 في هذا الملف، و `docs/03`.
- إن احتاج شيء إصلاحاً، ارفع الإصدار (1.8.5) وأضف قسماً في `CHANGELOG.md`، ثم ارفع بموافقة القائد مع وسم.

## 5. البيانات: الجهازان منفصلان حتى المرحلة ج

- **الخزنة:** لم تتغير على الماك (آخر تعديل 2026-11-13 من Windows). نفس الملف ونفس كلمة المرور.
- **على الماك تغيّر فقط:**
  - `data/device.json` (هوية الماك).
  - `data/harvest-state.json` (أرشفة جلسات Claude Code على الماك).
  - السجلات.
- **لا تُنسخ `data/` بين الجهازين يدوياً.** النسخ اليدوي قد يكتب فوق محادثات أو ذاكرة أحدث. المزامنة الصحيحة (مع قفل الكتابة) هي مهمة المرحلة ج.
- **`data/device.json` على Windows يبقى بهوية Windows.** هذا ما تحتاجه المرحلة ج: معرّفان مختلفان للجهازين.

## 6. المرحلة ج — المزامنة عبر Google Drive (التالية)

التفاصيل في [`docs/07-EXPANSION-PLAN.md`](07-EXPANSION-PLAN.md). نقاط تعلّمناها من الماك:

1. **هوية الجهاز جاهزة:** `data/device.json` فيه `deviceId` و `deviceName` و `platform` لكل جهاز:
   - Windows: `DESKTOP-…`، `windows`.
   - الماك: `MacBook-M5`، `macos`.
2. **حدّ معروف:** نقل المجلد من ماك إلى ماك آخر (نفس النظام) يُبقي الهوية القديمة. إن احتجنا ذلك، أضف بصمة جهاز (مثل `hostname` أو معرّف العتاد) إلى `install/device-identity.ts`.
3. **مسارات المشاريع لكل جهاز:** المشاريع الثلاثة على الماك بمسارات `D:\…`. يجب أن يحفظ كل جهاز مساره الخاص لكل مشروع، مفتاحه `deviceId`.
4. **الصوت لكل جهاز:**
   - اختيار صوت XTTS (`Suad Qasim` / `Damien Black`) محفوظ في متصفح كل جهاز (`localStorage`: `ttsSpeaker`)، لا في الإعدادات.
   - المحرك نفسه يختلف بين الجهازين: Windows = XTTS + Kareem، الماك = XTTS + Majed. **لا تُزامن `vendor/`.**
5. **الإعدادات:** `config/settings.json` غير مرفوع. انتبه عند مزامنته لأن فيه مسارات خاصة بكل جهاز.

### ثم المرحلتان د و هـ
- **د — Ollama الموزّع:** المكتبي RTX 3090 عبر Cloudflare، والبند أ٢.4 `ollama launch claude`، و XTTS على المكتبي، وقائمة اختيار النموذج.
- **هـ — «أجهزتي»:** RustDesk و Wake-on-LAN.

## 7. قواعد ملزمة (مختصر الدستور)

- **الردود بالعربية.** الاسم: «Second Brain» أو «العقل الثاني».
- **المستودع عام:**
  - يُرفع الكود والوثائق فقط، **وبموافقة القائد الصريحة**.
  - لا يُرفع `data/` ولا `vendor/` ولا `config/branding.json` ولا `config/settings.json`.
  - قبل كل commit يُفحص التغيير بحثاً عن البريد والأسرار واسم المستخدم.
- **القانون التاسع:** كل تعديل يرفع الإصدار في `Second-Brain-System/package.json`، ويُضاف قسم في `CHANGELOG.md`. الإصلاح التالي **1.8.5**، والمرحلة ج **1.9.0**.
- **تسجيل الدخول** لأي حساب يقوم به القائد بنفسه. أي تنزيل يُعرض أولاً مع الحجم والمصدر.
- **الاختبارات** لا تلمس البيانات الحقيقية.
